# AI2 Text Factors

Исследовательская реализация разреженной ассоциативной памяти для поиска
повторяющихся факторов в потоке текста.

Проект развивает идеи эксперимента
[«Факторы в тексте»](https://github.com/aldrd/aboutbrain/tree/master/%D0%A4%D0%B0%D0%BA%D1%82%D0%BE%D1%80%D1%8B%20%D0%B2%20%D1%82%D0%B5%D0%BA%D1%81%D1%82%D0%B5),
но написан с нуля на Python. Исходный VB.NET-код и приложенные к нему книжные
корпуса сюда не копируются.

## Что уже работает

- детерминированное разреженное кодирование пар «символ–позиция»;
- латиница и кириллица, настраиваемый односимвольный алфавит через API/CLI;
- несколько циклических контекстных интерпретаций окна;
- случайные локальные рецептивные поля;
- создание, проверка, подрезание и консолидация кластеров памяти;
- режим поиска факторов без учителя;
- экспериментальный режим обучения преобразованию одного контекста в другой;
- объяснение выходного фактора через наиболее связанные символы и позиции;
- безопасное сохранение модели в сжатый NPZ без `pickle`;
- CLI и автоматические тесты.

## Новое в v0.2

- Цифры и ASCII-знаки различаются по умолчанию; пробелы и `_` остаются
  разделителями. Регистр по-прежнему сворачивается.
- Невозможные кодовые книги и повреждённые массивы отклоняются явно.
- Расширение алфавита и обработка потока частями имеют отдельные API.
- NPZ v2 сохраняется атомарно; режимы обучения не смешиваются незаметно.
- Добавлен экспериментальный стенд с базовыми методами, настройкой порога
  только на dev и полными JSON-трассами.
- Отдельный микромир проверяет активный выбор наблюдения из двух заранее
  заданных гипотез. Он **не подключён к SDR как обучаемая модель мира**.

## Экспериментальная v0.3.0a1: факторное ядро и контексты

- Добавлена консолидация по **совместным активациям** с ограниченной историей.
  Частотный режим остаётся исходной точкой сравнения и режимом по умолчанию.
- Повторная консолидация истории не создаёт новые наблюдения и не повышает
  счётчики подтверждений или стадии кластеров.
- Формат NPZ v3 сохраняет историю и дальнейшую траекторию обучения;
  настоящие архивы v1/v2 по-прежнему читаются.
- Новые стенды измеряют локальное восстановление факторов и целевого SDR
  на новых сочетаниях. Они показывают и отрицательные результаты.
- Экспериментальный `ExperienceMemory` соединяет факторную память с реальными
  парами «наблюдение — действие — последствие» и разными представлениями.
  Прогнозы и подтверждённые наблюдения разделены, повторные события не обучают
  память заново. Контексты, кодирование и возможные действия задаёт вызывающий код.

```bash
text-factors train --text "абракадабра абракадабра" --points 128 --consolidation coactivation --history-size 32 --model artifacts/joint.npz
text-factors factor-recovery --output artifacts/factor-recovery.json
```

Размеры экспериментов ограничены; стенды факторов и переноса проверяют бюджет
времени между вызовами и сохраняют статус таймаута. Для полного ограничения
одного зависшего вызова запускайте процесс с внешним таймаутом. Число точек,
кластеров и сохранённых строк определяет расход памяти; ограничение истории
одного кластера не означает небольшой общей памяти при любых настройках.

## Быстрый запуск

```bash
text-factors demo --text "абракадабра абракадабра абракадабра"
```

Обучение на UTF-8-файле:

```bash
text-factors train \
  --input corpus.txt \
  --model artifacts/model.npz \
  --epochs 3
```

Анализ без изменения модели:

```bash
text-factors analyze \
  --model artifacts/model.npz \
  --text "абракадабра" \
  --top 10
```

Строки длиннее размера кадра автоматически анализируются как последовательность
перекрывающихся окон.

## Python API

```python
from text_factors import ModelConfig, TextFactorModel

config = ModelConfig(point_count=4_000, seed=42)
model = TextFactorModel(config)
model.fit_text("абракадабра абракадабра", epochs=5)

result = model.transform_window("абрак")
print(result.to_dict())

for factor in model.top_factors(5):
    print(factor.to_dict())
    print(model.explain_factor(factor.output_bit, limit=5))

model.save("artifacts/model.npz")
restored = TextFactorModel.load("artifacts/model.npz")
```

## Воспроизводимые эксперименты

```bash
text-factors evaluate --output artifacts/evaluation.json
text-factors microworld --seed 42 --episodes 32 --action-budget 1 --output artifacts/microworld.json
```

Первый вызов сравнивает факторную память с точным запоминанием, биграммами,
ближайшим SDR и обучаемой парой позиций. Для всех методов используются одни и
те же положительные обучающие строки и число предъявлений. Порог вычисляется
по отрицательным dev-примерам; test не используется для настройки.

Второй вызов — отдельная положительная проверка протокола
«неопределённость → информативное действие → перенос». Объекты и две гипотезы
даны разработчиком; это не открытие новых правил нынешней SDR-памятью.
Подробности: [MICROWORLD.md](docs/MICROWORLD.md).

JSON содержит данные, конфигурацию, хеши исходников, сырые оценки, решения и
метрики. Значения метрик воспроизводимы при тех же версиях зависимостей; время
исполнения зависит от машины. Существующий отчёт не перезаписывается без
`--overwrite`. Первые результаты и дальнейшее решение:
[V02_RESULTS.md](docs/V02_RESULTS.md).

## Старые модели и потоковый ввод

```python
from text_factors import TextFactorModel

model = TextFactorModel.load("artifacts/old-model.npz")
# v1 не хранила режим. Указывать его можно только зная происхождение модели:
model.assume_training_mode("unsupervised")
model.encoder.extend_alphabet("0123456789+-=?!")

for window, offset in model.encoder.iter_chunked_windows(["абра", "кадабра"]):
    model.partial_fit_window(window, offset=offset)
model.save("artifacts/model-v2.npz")
```

Чтение v1 не требует выбора режима. Неизвестный режим блокирует именно
продолжение обучения. Для старой supervised-модели нужно также указать
`source_context` и `target_context`. Одна `TextFactorModel` обучает одну
такую пару. Экспериментальный банк отдельных отображений уже доступен
через [ExperienceMemory](docs/EXPERIENCE.md); сохранение всего банка
и самостоятельное открытие операторов пока не реализованы.

`fit_text()` при каждом вызове обрабатывает отдельный документ. Для одного
потока по кускам используйте `iter_chunked_windows()`; его окна и смещения
совпадают с обработкой склеенного документа.

Подробное описание математики и отличий от прототипа находится в
[`docs/ALGORITHM.md`](docs/ALGORITHM.md).
