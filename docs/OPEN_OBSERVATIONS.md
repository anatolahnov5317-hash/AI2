# Открытые наблюдения и идентификаторы экземпляров

Первая поставка плана работы с реальными данными добавляет маршрут
`text-factors observations`. Он сохраняет произвольный корректный UTF-8,
исходные координаты, версии документов и явную внешнюю разметку экземпляров.
Упоминания и привязки на этом этапе задаёт разметчик или адаптер данных.
Автоматическое выделение сущностей и понимание новых слов здесь не реализованы.

## Быстрый запуск

```bash
python -m pip install -e .
text-factors observations import --archive observations.sqlite --input document.txt --namespace pilot --source-key document-1 --group document-family-1 --origin user-provided
text-factors observations list --archive observations.sqlite --namespace pilot
text-factors observations verify --archive observations.sqlite
```

В ответе импорта есть `source_id`, номер версии, SHA-256, размеры и число
фрагментов. Статус `uninterpreted` означает, что данные сохранены, но их смысл
ещё не установлен. Имена и слова из `learning/language_data.py` не используются.

Для чтения страницы используйте ID, полученный при импорте:

```bash
text-factors observations show --archive observations.sqlite --source SOURCE_ID --version 1 --offset 0 --limit 20
```

`next_offset` позволяет получить следующую страницу; пустая страница завершает
чтение. Для списка источников аналогично используется `--after` и `next_cursor`.
Версия при `show` необязательна: без неё возвращается последняя завершённая.
Для разметки версия обязательна, чтобы координаты не перенеслись на другую
редакцию документа.

## Какие гарантии даёт слой

- Исходные UTF-8 байты восстанавливаются точно, включая BOM, CRLF, комбинируемые
  символы, регистр и `е/ё`. Неверный UTF-8 отклоняется без замены символов.
- Строки разбиты на ограниченные фрагменты с координатами в кодовых точках
  Unicode и в байтах UTF-8. Граница фрагмента не является границей события.
- SHA-256 хранится для документа и каждого фрагмента; `verify` проверяет
  контрольные суммы, непрерывность координат и ссылки.
- Повторный импорт того же содержимого и метаданных с тем же внешним ключом
  возвращает прежнюю версию. Изменение содержимого или метаданных создаёт новую.
- Два документа с одинаковыми байтами и разными внешними ключами сохраняют
  разные идентификаторы и происхождение. Совпадение хеша не объединяет сущности.
- Записи дописываются; старые источники, упоминания и версии привязок не меняются.
- Один импорт и один пакет разметки — отдельные атомарные транзакции.
  Ошибка, нехватка бюджета или смерть процесса не оставляют половину пакета.
- Два экземпляра с одним названием имеют разные ID. Совпадение строки не
  является решением о тождестве.
- Неоднозначная привязка хранит несколько кандидатов без выбранного;
  неразрешённая — пустой набор кандидатов.

SQLite использует WAL, `synchronous=FULL` и внешние ключи. Триггеры запрещают
обычные UPDATE/DELETE исходных записей. Это контроль целостности приложения;
он не является защитой от владельца файла, намеренно переписывающего саму БД.
`namespace` предотвращает связывание экземпляров разных пространств, но не
заменяет аутентификацию и авторизацию файлового сервиса.

## Идентичность и внешняя разметка через API

Пример ниже содержит явно заданную человеком разметку. Он показывает передачу
двух одинаково названных экземпляров через новый интерфейс.

```python
from text_factors.observations import ObservationArchive

text = "Первый ключ здесь. Второй ключ там."
with ObservationArchive("observations.sqlite", create=True) as archive:
    source = archive.import_text(
        text,
        namespace="example",
        external_key="two-items",
        group_id="two-items-dialogue",
        metadata={"origin": "explicit example", "author": None},
    )
    first = text.index("ключ")
    second = text.index("ключ", first + 1)
    result = archive.annotate({
        "schema": "ai2-open-annotations-v1",
        "source_id": source.source_id,
        "source_version": source.version,
        "annotator": "human-example",
        "evidence": "Explicitly marked first and second objects",
        "instances": [
            {"ref": "a", "external_key": "key-1", "label": "ключ"},
            {"ref": "b", "external_key": "key-2", "label": "ключ"},
        ],
        "mentions": [
            {
                "start": start,
                "end": start + 4,
                "surface": "ключ",
                "candidates": [ref],
                "selected": ref,
                "expected_version": 0,
            }
            for start, ref in [(first, "a"), (second, "b")]
        ],
    })
    assert result["instances"]["a"]["instance_id"] != result["instances"]["b"]["instance_id"]
    print(result)
```

Тот же пакет можно подать файлом:

```bash
text-factors observations annotate --archive observations.sqlite --data annotations.json
text-factors observations annotations --archive observations.sqlite --source SOURCE_ID --version 1
```

`start/end` — полуоткрытый интервал `[start, end)` в исходном декодированном
тексте. Нельзя предварительно убрать BOM, преобразовать CRLF в LF или применять
нормализацию и затем использовать координаты изменённой строки. `surface`
проверяется по оригиналу, включая фрагменты, пересекающие границы хранения.

`external_key` экземпляра задаётся данными и стабилен внутри namespace.
Разные ключи создают разные экземпляры независимо от одинаковой метки.
Чтобы использовать уже существующий экземпляр, можно передать
`{"ref": "a", "instance_id": "inst_..."}`. Его метка не ограничивает допустимые
формы последующих упоминаний.

Для неоднозначности укажите `candidates: ["a", "b"]`, `selected: null`.
Для неразрешённого упоминания — пустой список и `null`. При исправлении
передайте тот же интервал, новую привязку и `expected_version`, равный последней
версии привязки. Устаревшая запись отклоняется целиком. Повтор идентичного
пакета после потерянного ответа допускается и не создаёт дубли.

Статус `annotated` означает решение внешнего разметчика, а не подтверждённый
факт мира или результат автоматической кореференции. Версию разметки можно
прочитать отдельно через `get_binding(mention_id, version)`.

## Фиксация корпуса для последующего обучения

Создайте спецификацию:

```json
{
  "schema": "ai2-open-corpus-splits-v1",
  "assignments": [
    {"source_id": "SOURCE_ID", "source_version": 1, "split": "train"}
  ]
}
```

```bash
text-factors observations freeze --archive observations.sqlite --data splits.json --output corpus.json
text-factors observations validate-corpus --archive observations.sqlite --data corpus.json
```

Manifest закрепляет версии источников и разметки, происхождение через хеш
метаданных и SHA-256 содержимого. Новое исправление не меняет старый corpus.
Поддерживаются `train`, `validation`, `test`. Между ними запрещено делить
одну заявленную группу источников и идентичное содержимое, даже если оно
заведено под разными именами. Один manifest относится к одному namespace.

Группы задаёт подготовка данных. Автоматического поиска близких перепечаток,
заимствований и смысловых дублей пока нет. Результат валидации прямо содержит
`near_duplicate_independence_verified: false`.

Manifest привязан к ID конкретного архива. При создании нового архива ID будут
другими; исходники проверяются по своим хешам и внешним ключам. Для переноса
готового корпуса нужно переносить архив с сохранением ID, а не создавать его
заново и подставлять старые ссылки.

## Ресурсы и восстановление

По умолчанию: фрагмент 2048 кодовых точек, источник до 64 МиБ, извлекаемый span
до 8192 кодовых точек, пакет до 10000 аннотаций/экземпляров. Это конфигурация
ресурсов, а не словарь языка. CLI позволяет задать `--chunk-chars` и
`--max-bytes`; остальные параметры доступны через `ArchiveLimits`.

Файлы читаются порциями по 65536 байт, импорт не собирает весь корпус в один
JSON. Одна большая транзакция ограничена размером одного источника. Завершённые
источники переживают прерывание; текущий незавершённый источник после
перезапуска импортируется сначала. Внутрифайлового checkpoint пока нет.

Для корректной резервной копии SQLite используйте его backup API либо
копируйте после закрытия всех соединений. Копирование одного основного файла
при активном WAL может потерять завершённые записи. Архив содержит исходные
данные; его доступность определяется правами на файл и окружающим сервисом.

## Граница первой поставки

Новый слой готов принимать результаты будущего обучаемого выделения упоминаний
и связывания экземпляров. Веса существующего `learned-chat` и его парсер не
изменены: их прежние ограничения сохраняются. В частности, успешная внешняя
разметка двух ключей не закрывает языковую ошибку L10 старого диалога.
