# P22: независимая оценка и заморозка

Статус: **протокол до закрытого испытания**. Открытая программа
`scripts/evaluate_p22_open.py` проверяет только механизм на явно придуманных
русских примерах. Она отвергает `sealed_test`, `calibration` и `future_stream`.
Это намеренно: независимого разрешённого русского набора, владельца проверки и
установленных порогов P01 пока нет. Из старых GUM-результатов нельзя делать
новую закрытую проверку.

## Разделение и заморозка

1. Для каждой истории, редакции, перепечатки и исправления записать одно
   проверенное человеком семейство. Сохранить оригинальные байты, версию,
   происхождение эталонной метки, SHA-256, право использования и маску
   полноты разметки. Недостающая метка не является отрицательной.
2. Независимый хранитель до запуска фиксирует семейства для `train`,
   `development`, `calibration`, `sealed_test`, `future_stream`. Цепь исправлений
   остаётся в одном разделе. Разработчик не получает текст, разметку или
   идентификаторы закрытой выборки; хранитель сообщает только commitments.
   Недостаточно программной проверки равенства ID: человеческая проверка
   зависимости копий и семейств необходима.
3. До получения закрытых ответов поместить в версионированный freeze-manifest:
   полный commit и tree кода; SHA-256 сериализованной модели и всех весов;
   SHA-256 протокола, кода оценщика и порогов; manifest и commitments разделов;
   список метрик и знаменателей; целевые отношения и горизонт прогноза;
   версии Python/зависимостей; компьютер и бюджеты; IDs baseline и ablations;
   seed, число bootstrap повторений, правило отказа, список исключений и
   правило остановки. Подписанное независимым хранителем подтверждение
   заморозки должно иметь дату и предшествовать выдаче test.
4. `calibration` применяется только до этого шага. На `sealed_test` один
   заранее зарегистрированный прогон без обучения, перенастройки или выбора
   лучшего seed. Если результат подсказал правку, эта выборка навсегда
   считается раскрытой и следующая закрытая оценка требует новые группы.
   Отдельный будущий поток допускает только объявленное заранее
   `predict → reveal → score → update` по времени.

Пока нет отдельного хранителя, валидного sealed commitment и подписанной
заморозки, **закрытый запуск блокирован**. Нынешний локальный evaluator
отказывается оценивать любой раздел кроме открытого `development`; для
реального sealed понадобится отдельная служба независимого хранителя с
одноразовым журналом использованных commitments. Передачу набора прямо в
исследовательскую программу нельзя считать таким запуском.

## Общие знаменатели и сравнения

Единица независимости — семейство истории, не сообщение. Все методы получают
одни и те же входы и до раскрытия эталона фиксируют предсказание или отказ.
Каждый case имеет полностью размеченный для измеряемой задачи gold;
неполная разметка отклоняется. Отдельные представления события, роли, времени,
отрицания, подтверждённого факта и прогноза оцениваются по договорённой схеме,
без смешивания прогнозов после обновления с предсказаниями. Нужны как минимум
следующие срезы: новая для **старого baseline** связь, изученная только на
`train` и проверенная на новом семействе; полностью новое отношение без
обучения (нулевой перенос, считать отдельно); новая история и временной поток;
длинные и конфликтные тексты; точная цель исправления и сохранение доступа.

Открытый оценщик сейчас реализует узкий срез точных структурных событий:
полный набор меток в вопросе, полнота pointers по каждому принятому
утверждению, отказ и ошибки. Указание адреса источника **не доказывает**
действительность текста или права доступа: в сквозной проверке обязательно
проверять настоящий receipt P18–P20 на актуальных версиях. Полезное покрытие
отдельного семейства в этом срезе равно 1 только если **все** его вопросы
приняты точно и имеют pointers. Доля рискованных принятых семейств считает
каждое семейство один раз, если хотя бы один принятый ответ неверен или
не имеет pointers. Публиковать числители и знаменатели вместе с отказами.

Показать baseline с одинаковыми данными и временем доступа, вариант с
выключенным исследуемым компонентом и попарные разницы внутри каждого
семейства. Скрипт публикует двухсторонний Wilson 95% для долей по семействам,
seeded bootstrap для попарной разницы и Wilson для доли выигрышей среди
не-ничьих. При малом числе групп bootstrap может выродиться и не является
доказательством превосходства. Для строгих ворот P24 использовать отдельно
предзаданную **одностороннюю точную** верхнюю биномиальную границу на
независимых принятых историях, а не этот диагностический Wilson.

## Все запуски и расходы

Каждое выполнение начинается с новой записи `started` в SQLite с `FULL`
synchronous; после результата сохраняется `finished` с полными построчными
ответами, commit/tree/флагом грязного дерева, SHA модели и fixture, seed,
счётчиками, доверительными интервалами, wall/CPU временем, верхним RSS
процесса, версией Python и архитектурой. Исключение фиксируется как `failed`;
аварийный kill оставляет видимое `started`. Повтор создаёт новый run ID, не
заменяет старый. Пользователь/хранитель публикует **весь** ledger вместе с
отчётом, в том числе неудачные и незавершённые попытки; обычный локальный
SQLite не является защитой от умышленного удаления файла администратором.
Проверка такого удаления и независимое архивирование относятся к будущему
хранителю sealed. Для воспроизводимого открытого прогона:

```bash
PYTHONPATH=src python scripts/evaluate_p22_open.py --ledger /path/to/p22-all-runs.sqlite
```

Не объявлять P22, P24 или пилот пройденными, пока нет разрешённого corpus,
внешней заморозки, независимого запуска по этому протоколу, опубликованного
полного журнала и проверки заранее утверждённых критериев P01/P24.
