# P24. Ворота теневого и ограниченного пилота

Статус на 23 сентября 2026: **только проверка механизма на искусственных
данных; реальный пилот заблокирован**. Прежде чем получать реальные данные и
выдавать ответы пользователям, требуется завершить паспорт
[`pilot_contract.yaml`](pilot_contract.yaml), протокол независимых семейств
P01/P02, права на источники и устройство проверки. Сейчас валидатор показывает
21 незаполненное решение. Условный проход блока 1 разрешает разработку, но
не подтверждает качество пилота.

## Порядок запуска

1. Владелец фиксирует один русский процесс, источники, роли доступа,
   разрешённые вопросы, цену ошибок и целевой компьютер. Независимый хранитель
   подтверждает права, происхождение разметки, семейства документов и историй
   задач. Перед испытанием замораживаются код, версии, пороги и вопросы: по
   одному заранее выбранному вопросу из каждого независимого семейства.
2. На **теневом** потоке записываются запрос, решение о разрешимости до
   ответа, отказ либо принятый ответ, текст, точный источник, версия и
   состояние прав на момент публикации. Исправления и отзыв прав проверяются
   сквозным сценарием; при критической ошибке публикацию остановить.
3. После проверки полного теневого журнала и разрешения владельца можно
   отдельно готовить **ограниченную** выдачу только в утверждённой области.
   Локальный JSON не может доказать полномочия владельца. Машинный оценщик
   никогда сам не включает выдачу.

## Метрики и знаменатели

| Показатель | Числитель / знаменатель | Ворота |
|---|---|---|
| Полезное покрытие | Заранее признанные разрешимыми вопросы с принятым, полезным и подтверждённым ответом / все заранее признанные разрешимыми вопросы | Не ниже 70%; отказ уменьшает покрытие |
| Риск неподтверждённого ответа | Принятые ответы с хотя бы одним неподтверждённым либо существенно неверным утверждением / все принятые содержательные ответы | Верхняя **точная односторонняя** 95% граница не выше 1% |
| Атрибуция | Принятые ответы с действительным разрешённым источником и точной версией / все принятые содержательные ответы | 100% |

Для `e` ошибок среди `n` независимых принятых ответов граница — верхняя
Clopper–Pearson: решение `P(Binomial(n, p) ≤ e) = 0,05`, а при нуле ошибок
`1 − 0,05^(1/n)`. Даже для нуля ошибок нужны **не меньше 299** независимых
принятых ответов, чтобы пройти 1%. При `n=0` оценка риска не определена.
При неизвестной разметке, повторе семейства, отсутствии версии или критической
ошибке ворота блокируются; по утверждённому P01 протоколу независимость
подтверждает человек, а не похожесть `group_id` в JSON. Подвыборка из потока
с одним вопросом на историю характеризует именно этот способ отбора, не все
будущие пользовательские запросы.
Принятый содержательный ответ на заранее признанный неразрешимым вопрос
считается рискованным даже при ошибочной метке «ошибок нет». Ответ без
действительного разрешённого источника не считается полезным и подтверждённым.

## Открытая машинная проверка

`src/text_factors/real_data/pilot_readiness.py` отказывается считать повтор
одной истории новым испытанием, не записывает неизвестное как безопасность,
считает покрытие с отказами и использует точный биномиальный интервал.
`scripts/score_p24_pilot.py` дополнительно проверяет P01, записывает ссылки
на заморозку, независимую группировку и разметку. Схема входа
`ai2-p24-trials-v1` содержит `phase: shadow|limited`, четыре ссылки на
подтверждения и массив `trials`; каждому элементу требуются `group_id`,
`query_id`, `preselected: true`, `answerable`, `accepted`, а для принятого
ответа оценки `useful_supported`, `unsupported_or_wrong`,
`authorized_source_and_version`. Неизвестное значение — `null`.

```bash
PYTHONPATH=src python scripts/score_p24_pilot.py \
  --input /path/to/frozen-trials.json \
  --contract docs/real_data/pilot_contract.yaml
```

Пока P01 черновой, программа возвращает `status: blocked` и код 2 даже при
идеальных искусственных цифрах. Ограниченный поток дополнительно блокируется
до проверенного отчёта теневого потока и разрешения владельца. Если все
машинные проверки теневого потока пройдут, статус будет
`ready_for_owner_review`, а `pilot_activated` всё равно `false`.
Ссылки из JSON остаются заявлением вызывающего, содержимое и подпись должен
проверить независимый хранитель. Тесты механизма не заменяют реальную
оценку P22, полный журнал и измерение на выбранном оборудовании P23.
