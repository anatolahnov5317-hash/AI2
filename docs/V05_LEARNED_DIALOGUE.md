# AI2 v0.5: шесть этапов обучаемого диалога

Новый режим `learned-chat` соединяет четыре обучаемых компонента, структурную
память событий и отдельную систему проверки. Обучение выполняется локально
на CPU; зависимости — Python 3.10+ и NumPy. Готовая LLM, внешние API и загрузка
чужих весов не используются. Результат остаётся исследовательским диалогом
о людях, предметах, местах и передачах. Свободная беседа обо всём не заявляется.

## Запуск

Из корня репозитория:

```bash
python -m pip install -e .
python -m text_factors learned-train --output learned-model.json --seconds 120
python -m text_factors learned-chat --model learned-model.json --demo
python -m text_factors learned-chat --model learned-model.json --state learned-session.json
```

`/quit` завершает разговор. Повтор последней команды продолжает сохранённую
сессию. Модель обучается отдельной командой: обычные сообщения пользователя
меняют память разговора, но не обученные параметры. Новый файл модели нельзя
незаметно подставить в старую сессию: проверяется отпечаток всех параметров.
Старые команды `converse` и `chat` остаются отдельными режимами.

Для программного вывода:

```bash
python -m text_factors learned-chat --model learned-model.json --json --message "Петя передал книгу Маше" --message "У кого книга?"
```

Ответ JSON содержит выбранное действие, структуру смысла, факты, источник,
диагностику модели переходов и проверенные сегменты генератора. Уверенность
компонентов — диагностическая оценка, не откалиброванная вероятность истины.

## Что реализовано по каждому пункту

| Этап | Обучаемая часть | Явно заданная опора и граница |
| --- | --- | --- |
| 1. Понимание реплики и контекста | Линейные семантические головы, оценка ролей и выбор референта обучаются на целых размеченных репликах и контекстах | Токенизация, признаки, конечные формы сущностей и словарь обучения заданы; незнакомые слова могут привести к отказу |
| 2. Структура смысла | Модели предсказывают участников, предикат, отрицание, время, вложенность и тип реплики | Типизированное дерево `Meaning/Event/Query`, роли и допустимые области действия заданы программой |
| 3. Изменения ситуаций | Настоящее факторное ядро учит эффекты из «до → событие → после» и сопоставляет контекстные трактовки с общей памятью опыта | Базис ролей и преобразования контекстов ограничены; открытие произвольных новых понятий не реализовано |
| 4. Продолжение диалога | Политика обучается на последовательностях с ответами, уточнениями, незнанием, исправлениями и источниками | Проверка допустимости действий запрещает ответ без фактов и запись неподтверждённых эффектов |
| 5. Формулировка ответа | Условная токенная модель учит вероятности продолжения и копирование аргументов, декодирует по токенам | Небольшой словарь, ограниченная длина и отдельная проверка утверждений; это не универсальная языковая модель |
| 6. Обучение и проверка | Раздельные разметки языка, переходов и диалогов; сохранение действительных численных параметров | Независимые проверочные семейства, контрольные модели, фиксация исходников и полные знаменатели ошибок |

«Маша получила книгу от Пети» и «Петя передал книгу Маше» должны давать одно
событие передачи с теми же ролями. Соответствие формулировки смыслу обучается;
отдельного правила для этих двух строк в исполняемом разборе нет. Учебные
формулировки и словоформы, включая этот пример пользователя, раскрыты в данных.
Проверка именно этих строк является приёмочной, а не независимой проверкой
переноса. Перенос оценивается на других заранее отделённых формулировках.

Обещание содержит вложенное событие передачи, однако само по себе не меняет
владельца книги. Отрицание совершения передачи также не доказывает, у кого
находится предмет. Условия и сообщения другого лица сохраняются как области
действия; автоматическое превращение их содержимого в факт запрещено.

Время хранится как категория события. Запрос исторического состояния требует
определённой временной привязки; произвольные даты и временной вывод ещё не
поддержаны. Сложная фраза с отдельными условием и следствием может быть
отклонена целиком. После уточнения надёжнее повторить полную реплику: свободное
заполнение пропущенного аргумента коротким ответом ещё не реализовано.

## Данные и собственное обучение

```bash
python -m text_factors learned-export-data --output training.json
python -m text_factors learned-train --data training.json --output custom-model.json
```

Экспорт содержит только учебные примеры. Формат `ai2-learning-data-v1`:

- `understanding`: текст, правильное дерево смысла, контекст, семейство
  конструкции и размеченные ссылки `links`;
- `transitions`: списки фактов `before` и `after` и структурное `event`;
- `dialogues`: последовательности размеченных реплик с признаками задачи,
  правильным действием, текстом ответа, слотами копирования и опорными фактами.

Текущие пределы: 2048 языковых примера, 512 переходов, 128 диалогов и суммарно
2048 диалоговых реплик. Учебные ограничения нужны для воспроизводимого опыта
на одном компьютере. Загрузка книги в старую команду `train` обучает другое
текстовое ядро и сама по себе не создаёт разметку ролей и диалогового поведения.

Исправления модели оформляются как исправленные обучающие примеры и новое
явное обучение. Команда `--overwrite` разрешает заменить существующий файл
того же типа; посторонний файл состояния или модели не перезаписывается.

При собственном обучении понимания также используется раскрытая в исходниках
учебная программа разрешения ссылок `reference_examples()` и конечная таблица
форм сущностей. Эти опоры входят в описание происхождения модели; они не
выводятся автоматически из произвольного корпуса. Отпечаток обучения включает
переданные языковые примеры и встроенную программу ссылок. Длительность
обучения — диагностические данные: при повторном обучении она может отличаться
при совпадении численных параметров.

## Проверка и защита от зависаний

```bash
python -m text_factors learned-evaluate --model learned-model.json --split development --output development.json
python -m text_factors learned-freeze --model learned-model.json --output freeze.json
python -m text_factors learned-evaluate --model learned-model.json --split held_out --freeze freeze.json --output held-out.json
```

Для самостоятельных экспериментов следует создать новые независимые примеры:
опубликованный тест, по ошибкам которого уже менялась модель, становится
данными разработки. Полный протокол — [V05_EVALUATION_PROTOCOL.md](V05_EVALUATION_PROTOCOL.md).

Обучение и CLI-реплики работают в отдельном процессе с жёстким пределом
времени. По умолчанию это 120 секунд обучения плюс ограниченный запас
супервизора и 15 секунд на запуск, восстановление и обработку реплики.
Внутри реплики действует дополнительный бюджет 2 секунды. Вход ограничен
2048 символами и 96 токенами; число событий — 512, контекст — 16 реплик.
Предельный JSON модели — 12 МБ, сессии — 3 МБ, полного сообщения процессу —
16 МБ. Генератор ограничен 48 токенами на сегмент и числом подтверждённых фактов.

Изменения памяти транзакционные: неуспешный разбор, неразрешённый эффект,
ошибка генерации или тайм-аут не записывают частичную ситуацию. Снимки
сохраняются атомарно; контрольная сумма выявляет повреждение файла.
Загрузка проверяет размеры, конечность чисел, историю событий и основания
сохранённых ответов. Контрольная сумма не является цифровой подписью.
Супервизор ограничивает собственные вычисления программы; это не песочница
для исполнения недоверенного кода. Проверка процессов выполнена на Linux;
очистка дочерних процессов Windows требует отдельной проверки на Windows.

Проверка генератора удостоверяет соответствие сказанного памяти и слотам.
Она не доказывает, что языковой модуль правильно понял исходную фразу:
качество понимания и фактические ошибки измеряются отдельно.

## Связь с работами Редозубова

Часть 2 «Формализации смысла» связывает контекст с преобразованием описания,
памятью опыта и сравнением полученной трактовки с этой памятью. Поэтому
здесь отдельно существуют предсказание перехода и сравнение контекстных
трактовок с общей памятью; они не объявляются одним и тем же алгоритмом.
Ролевой базис, лингвистические признаки, политика диалога и языковой генератор
являются инженерными решениями этого проекта. Часть 3 не даёт готового
алгоритма свободного чата и оставляет дальнейшую семантическую обработку
и обучение поведения предметом исследования.

- [Редозубов, часть 2: «Пространство контекстов»](https://www.ontology-of-designing.ru/article/2021_3%2841%29/Ontology_Of_Designing_3_2021_4_A.D.Redozubov_309-319.pdf).
- [Редозубов, часть 3: «Формирование контекстов»](https://www.researchgate.net/publication/357581656_Formalization_of_the_meaning_Part_3_Formation_of_contexts).
- [Обучение следованию инструкциям по демонстрациям и обратной связи](https://arxiv.org/abs/2203.02155). Здесь реализовано обучение по демонстрациям, без заявления о реализации RLHF.
- [LongMemEval](https://arxiv.org/abs/2410.10813): отдельная оценка памяти, обновлений и правильного незнания; собственные тесты AI2 не являются результатом на этом бенчмарке.
