# AI2 v0.4.0a1: grounded Russian dialogue

## Что реализовано

Это вертикальный прототип ограниченного диалога, построенный поверх
исследовательского ядра v0.3.0a4. Он не заменяет прежние эксперименты,
не использует внешнюю LLM и не выдаётся за модель свободного русского языка.

| Этап | Реализация | Что здесь обучается |
|---|---|---|
| Смысловая структура | Роли участника, предмета, места, получателя; отрицание, время, модальность, тип сущности | Грамматика и типы заданы явно |
| Интерпретация действия | Словесный сигнал → LearnedSDRTransform → общая память → факторный портрет | Ассоциативная связь обучающей пары |
| Память ситуации | Журнал событий, текущие факты, источники, темы, исправление и отмена | Правила обновления заданы явно |
| Управление диалогом | Ответ, уточнение, признание незнания, обучение, смена темы | Политика задана явно |
| Формулировка | Ответ только по подтверждённым фактам; конечная таблица падежей | Шаблоны, не обученная генерация |
| Обучение | 33 начальные пары; явная команда /teach; отказ при конфликте | Только лексические связи, не собственные догадки |
| Проверка | Замороженные диалоги, контроль без обучения, перемешивание целей, lookup и oracle | Измерение, а не добавочное обучение |
| Надёжность | Ограничения, транзакции, процессный тайм-аут, атомарное сохранение | Инженерная защита |

В режиме `factor` ответ требует и обученного преобразования, и общей памяти
факторных портретов. Тесты удаления каждого звена приводят к отказу узнавания.
Словарь обучающих целей не используется как запасной ответ при неудаче ядра.
Контроль `nearest` — открыто обозначенный точный поиск нормализованной строки;
это не ближайший сосед по выученному смыслу. `oracle` доступен только оценщику,
а производственная загрузка его не принимает.

## Быстрый запуск

Требования: Python 3.10+, NumPy 1.24+. Из корня репозитория:

```bash
python -m pip install -e .
text-factors converse --demo
text-factors converse --state conversation.json
```

Каталог для файла должен уже существовать. Повторная команда с тем же
`--state` продолжает сохранённую сессию. `/quit`, `/exit` или `выход` завершают
чат; ожидание пользовательского ввода не считается зависанием вычисления.

```text
Вы: Я положил ключ в ящик
AI2: Запомнил: Ключ в ящике.
Вы: Потом я переложил его в сумку
AI2: Запомнил: Ключ в сумке.
Вы: Где ключ?
AI2: Ключ в сумке.
Вы: Нет, ключ на столе
AI2: Исправил: Ключ на столе.
Вы: Отмени последнее утверждение
AI2: Отменил указанное утверждение; состояние восстановлено по оставшимся сообщениям.
Вы: Где ключ?
AI2: Ключ в сумке.
```

Поддерживаются также `Миша передал ключ Маше`, `У Маши есть книга`,
`У кого ключ?`, `Что у Маши?`, `Ключ в ящике?`, `Почему?`, `Тема: работа`.
`Почему?` объясняет **источник сведений**, а не физическую причину события.
Вопросы обновляют фокус разговора, но не создают факты. Их события сохраняются,
поэтому местоимения после перезапуска имеют тот же контекст.

Фразы без однозначного разбора отвергаются целиком: корректное начало
не записывается, если окончание непонятно. Неоднозначное местоимение вызывает
уточнение. Форматы с неизвестным склонением, опущенным подлежащим,
многословными сущностями и свободными причинными рассуждениями не поддерживаются.

Негативное утверждение `ключ не в ящике` отличается от `я не положил ключ в
ящик`: невыполненное действие не сообщает нового местонахождения. Будущее,
условие и предположение не записываются как установленные факты. Пересказ,
цитирование и непонятная модальность консервативно отклоняются.

Порядок состояний — порядок рассказанных сообщений. Это не временная база
данных: абсолютные даты, длительности и ретроспективная хронология не выводятся.
Местонахождение и владелец являются альтернативными ответами о положении
предмета в этом микромире; физическое местонахождение владельца не переносится
автоматически на предмет. Из сообщения о передаче не выводится юридическое право
собственности, причинность или проверенный факт реального мира.

## Обучение и программный интерфейс

```text
/teach спрятал move
Я спрятал ключ в сумку
Где ключ?
```

Допустимые учительские метки: `locate`, `move`, `give`, `have`. Они означают
место, перемещение, передачу и обладание в заданной онтологии. Грамматика
допускает не любое новое слово: первая версия принимает новые словесные сигналы
в ограниченных синтаксических формах. Неверная учительская метка может испортить
связь; дополнительные противоречивые пары вызывают отказ, а не голосование
по числу повторов. Исправить конфликт можно явным созданием проверенного
рецепта обучения через API; автоматического удаления прежнего обучения нет.

```python
from text_factors.conversation.engine import ConversationSession

session = ConversationSession(seed=42)
session.respond("Ключ в ящике", request_id="message-1")
answer = session.respond("Где ключ?", request_id="message-2")
print(answer.text)
print(answer.assertions)  # source, event_id, topic and typed fact
print(answer.evidence)  # factor evidence on turns with lexical interpretation
```

Прямой API проверяет кооперативный бюджет, но не может прервать зависший
низкоуровневый вызов. Для жёсткого ограничения используйте CLI или
`SupervisedConversation` из `conversation.runtime`: вся реконструкция модели
и обработка реплики выполняются в отдельном процессе.

Повторный `request_id` с тем же текстом возвращает исходный ответ, не повторяя
события и обучение. Другой текст с тем же ID отвергается. Гарантия действует
только пока квитанция хранится в ограниченной недавней истории.

## Ограничения и сохранение

| Ресурс | По умолчанию |
|---|---:|
| Длина реплики | 2048 символов |
| Токены / предложения | 128 / 8 |
| События / сущности | 512 / 256 |
| Недавние квитанции | До 128, дополнительно ограничены байтами |
| Уникальные обучающие пары | До 64 в факторном адаптере |
| Состояние | 4 000 000 байт |
| Внутренний бюджет реплики | 2 секунды |
| Процессный бюджет CLI с реконструкцией модели | 10 секунд |

Флаг `--timeout` меняет процессный лимит, `--turn-seconds` — внутренний лимит
для **новой** сессии. При восстановлении сохраняются прежние настройки.
Предел состояния процессного runtime — 12 МБ; прямой API допускает до 16 МБ.
Полный ввод и вывод рабочего процесса дополнительно ограничены 16 МБ.
Ответы с многими фактами показывают ограниченное число с явным указанием общего.

Сессия хранится как JSON с версией и SHA-256. Контрольная сумма обнаруживает
случайное повреждение, но не является криптографической аутентификацией.
Загрузка проверяет типы, объём, события, происхождение сохранённых ответов
и их соответствие формулировкам. Python-код и pickle не исполняются.

Численные памяти адаптера **реконструируются по ограниченному детерминированному
рецепту обучения**. Это не численный checkpoint и не продолжение произвольной
большой обученной модели. Такой формат добавляет стоимость реконструкции к
каждому supervised-запросу; предсказания и события проверяются на совпадение.

Запись выполняется атомарно, посторонний файл не принимается за сессию,
ссылки вместо конечного файла отклоняются. Сопутствующий `.lock` не удаляется:
блокировка ОС освобождается после завершения процесса и защищает от двух
одновременных CLI-писателей. Сетевые файловые системы и умышленно враждебные
процессы не входят в эти гарантии. POSIX проверен; ветвь Windows реализована,
но в данной среде не испытана. Это защита от обычных отказов, не песочница.

## Воспроизводимые проверки

```bash
python -m unittest discover -s tests -v
python -m ruff check .
python -m ruff format --check .
python -m pyright
text-factors dialogue-evaluate --split development --modes factor oracle --seeds 42
text-factors dialogue-evaluate --split held_out --seeds 7 17 42 --seconds 180 --output dialogue-report.json
```

Последняя команда сравнивает пять режимов на одном наборе диалогов. В отчёте
сохраняются ожидаемые/полученные факты, действия, все реплики, отказы,
неподтверждённые утверждения, время, seed и хеши кода/корпуса/обучения.
Завершение опыта (`status=completed`) не означает правильность всех ответов.
Прерванный опыт сохраняет завершённый префикс с явным неполным статусом;
он не выдаётся за полный результат. Качество свободной речи не измеряется.

Граница между обучением и проверкой зафиксирована в
[протоколе](V04_DIALOGUE_PROTOCOL.md) и [описании корпуса](V04_DIALOGUE_CASES.md).

## Связь с исходной исследовательской идеей

Связь с обсуждаемой у Редозубова интерпретацией через контексты и память
реализована в узком измеримом звене: обученное преобразование передаёт
результат в общую память факторных портретов. Грамматика, онтология и
диалоговая политика из этих работ автоматически не следуют — здесь это
явно выбранные инженерные компоненты. Предыдущая сверка с первоисточниками:
[V03A3_THEORY_AUDIT.md](V03A3_THEORY_AUDIT.md).

Для перехода к открытому чату ещё нужны обучаемая языковая интерпретация
и генерация, значительно более широкие данные, проверка новых слов/смыслов,
масштабируемая память и независимая оценка вне этого микромира. Успех на
нескольких десятках сценариев не доказывает эти способности и не показывает
преимущество над табличным baseline.
