# AI2 v0.3.0a3: преобразование, общая память и названия

Эта версия реализует четыре направления из
[аудита v0.3.0a2](V03A2_THEORY_AUDIT.md).
Параметры численных опытов зафиксированы в
[V03A3_PROTOCOL.md](V03A3_PROTOCOL.md) до первого запуска.
Изменения добавочные: прежние способы чтения и частотная консолидация
сохраняются, а новые механизмы включаются явно.

Первый фиксированный опыт подтвердил устойчивость названий при изменении
ключей в контрольном условии. В обученном сквозном пути названо только
8 из 135 проверочных частей: неполнота преобразования остаётся основным
наблюдаемым ограничением перед называнием. Подробные числа приведены ниже.

## Обученные преобразования перед общей памятью

`LearnedContextPipeline` принимает банк `LearnedSDRTransform` и одну
`CombinatorialMemory` для узнавания. Каждый преобразователь получает только
исходный SDR; предсказанный код передаётся в `recognize_views` этой общей
памяти. Пустой прогноз не подменяется исходным кодом или учебной целью.
Сохраняются контекст, предсказанные биты, шаг памяти преобразователя и
статус передачи в узнавание.

Разные представления должны заранее иметь согласованные области кодировки.
Одинаковая ширина SDR сама по себе не доказывает совпадение кодировок:
их идентификаторы и состав банка сообщает вызывающий код. Сам банк
контекстов не открывается автоматически.

```python
from text_factors import LearnedContextPipeline

pipeline = LearnedContextPipeline(
    common_memory,
    trained_transforms,
    input_encoding_id="sensor-v1",
)
result = pipeline.recognize(
    source_sdr,
    observation_id="observed-event-17",
    source_positions=(0,),
)
recognition = result.recognition
```

Границы исходного фрагмента задаёт адаптер. Обученная матрица преобразования
не предоставляет точного происхождения каждого выходного бита, поэтому
код не выдумывает такую атрибуцию. Памяти во время чтения не меняются;
их одновременное обучение другим потоком не поддерживается.
Сохранение всего банка преобразователей новым классом пока не реализовано;
памяти и их кодировки должен сохранять вызывающий слой.

## Близкие повторные отклики

`ContextAffinity` накапливает положительные и общие экспозиции пары контекстов.
Положительный пример требует одного наблюдения, одинаковых непустых позиций
происхождения и достаточного Jaccard-перекрытия факторных свидетельств.
Признак имеет вид `(точка памяти, совпавший входной бит)`. Названия контекстов
и равенство выходных битов не задают близость.

Обучение вызывается отдельно через `observe(event_id, recognition)`.
Повторная доставка того же события идемпотентна. Неполный результат не учит
карту. При запросе `select` выбирает сильный отклик и подавляет только его
непосредственных обученных соседей, которые достаточно похожи и сейчас.
Связи A–B и B–C не превращаются в автоматическое слияние A–C.
Разные позиции и явные противоречия сохраняются. Неполный поиск не служит
основанием убирать имеющихся кандидатов.

```python
from text_factors import ContextAffinity

affinity = ContextAffinity(recognition.encoding_id)
affinity.observe("distinct-training-event", training_recognition)
selected = affinity.select(query_recognition)
restored = ContextAffinity.from_dict(affinity.to_dict())
```

Это ограниченная инженерная модель совместных откликов. Она ещё не является
самоорганизацией полного пространства контекстов, метрикой семантической
эквивалентности или обучением логическим противоречиям.

## Названия при изменении кластеров

Точный `content_key` остаётся идентификатором набора свидетельств.
Опциональный `GroundingPolicy(mode="factor")` позволяет искать название
по прежним подтверждённым примерам, когда этот ключ изменился.
Сходство — число общих признаков, делённое на размер большего набора.
Так учитываются и потеря прежних признаков, и появление лишних.
Есть минимум свидетельств, порог и требование отрыва от другого названия.
Эта величина не является вероятностью.

Новые чтения не изменяют учебные примеры. Исправление названия исключает
поддержку исправленного подтверждения. Близкие конкурирующие названия
вызывают уточнение; большой вклад одной части вместе с отдельной знакомой
частью не должен превращаться в название целого по главной части.
Неизвестную помеху и неизвестный второй объект одними этими признаками
различить удаётся не всегда.

```python
from text_factors import GroundedDialogue, GroundingPolicy

dialogue = GroundedDialogue(
    recognition.encoding_id,
    output_width=common_memory.config.output_bits,
    grounding_policy=GroundingPolicy(mode="factor"),
)
dialogue.remember_recognition("scene-17", selected, encoding_id=recognition.encoding_id)
reply = dialogue.describe()
```

`resolve_candidate` возвращает слова, подтверждающие события, способ
узнавания, величину сходства, неоднозначность и прежние ключи свидетельств.
Для внешнего неархивированного кандидата нужно явно сообщить `encoding_id`.
Старый JSON v1 читается в точном режиме; JSON v2 сохраняет выбранную политику.
По умолчанию новый чат также использует точный режим.

Дополнительный режим доступен в существующем терминальном чате:

```bash
text-factors chat --demo --grounding factor --state artifacts/factor-chat.json
```

Этот чат по-прежнему использует заданные сдвиги текстовой модели. Банк
обученных SDR-преобразований включён в новый Python API и сквозной стенд;
загрузка такого банка в терминальный чат не предполагается данной командой.
Грамматика команд и шаблоны ответов остаются программными.

## Проверка совместной консолидации

```bash
timeout 40s text-factors coactivation-structure --output artifacts/joint-structure.json
```

Две явные совместные структуры сравниваются с перестановками колонок,
сохраняющими частоту каждого бита. Три порядка предъявления показывают
чувствительность к порядку. Внутри этого опыта алгоритм консолидации не
меняется. Отчёт содержит сами истории, веса, сырые маски и возможность
фактической подрезки с минимумом трёх рецепторов.

Пустая частотная маска здесь закономерна при частотах ниже 0.75.
В реальной памяти это ещё не означает автоматического удаления кластера:
подрезка должна пройти дополнительную проверку числа оставшихся рецепторов.
Порог частоты и порог максимальных нормированных весов имеют разные шкалы.
Поэтому это проверка механизмов и ограничений, а не доказательство общего
превосходства одного метода.

## Сквозной опыт и границы оценки

```bash
timeout 100s text-factors context-integration --output artifacts/context-integration.json
```

Отдельно оцениваются целые SDR и названия явно разделённых частей.
Сравниваются выученные преобразования, переставленные учебные цели,
необученные памяти и идеальное преобразование в отдельном контрольном
условии оценщика. Правильные цели не передаются рабочему преобразователю.

Слова сообщаются для канонических учебных частей. Затем проверяются новые
сочетания, неизвестные коды той же плотности и разные экземпляры.
После дополнительного обучения общей памяти другими наблюдениями прежние
вопросы повторяются без новых названий. Полнота битов, узнавание слова,
изменение ключа и подавление откликов измеряются раздельно.

Части повторяются в разных сценах, поэтому количество проверочных сцен
не равно количеству независимых новых содержаний. Заданные границы частей
не являются выученной сегментацией. Точно так же два независимо обученных
преобразователя одного отображения — заданное условие опыта; карта близости
не получает сведений об их тождестве от оценщика.

Размеры опытов и поисков ограничены. При превышении времени сохраняется
`incomplete`; финальная сводка не выдаётся за полный результат. Внешний
`timeout` ограничивает также отдельные вызовы, которые кооперативная
проверка времени не может прервать изнутри.

## Измеренные результаты

Исходный коммит: `4f1ff16ea9b0187d7fb18719dad8aa1e6dc97584`.
Из чистого этого коммита повторены оба опыта; все трассы совпали с первыми
прогонами. Сквозной повтор занял 7,31 секунды в текущем окружении.
Это время маленького стенда, не оценка скорости большой модели.

В test — 15 сцен, три контекстных трактовки каждой: 45 полных SDR и
135 запросов названий явно выделенных частей. Два контекста обучались
одному отображению независимо. Части повторяются, поэтому 135 запросов
не означают 135 независимых новых понятий.

| Условие | F1 битов целой сцены | Полнота битов целой сцены | Точных целых SDR |
|---|---:|---:|---:|
| Обученные преобразования | 0,8349 | 72,72% | 0/45 |
| Переставленные учебные цели | 0,2664 | 16,30% | 0/45 |
| Необученные преобразования | 0 | 0% | 0/45 |

Для отдельно предъявленных частей обученный преобразователь дал 347
верных битов, 43 лишних и 463 пропуска: полнота 42,84%, F1 0,5783.
В среднем получается 2,89 активного бита вместо шести целевых.
Это пересчёт сохранённых трасс, без нового обучения или подбора параметров.
В общую память до дообучения прошли 24 кандидата из 135 возможностей.

| Путь и состояние общей памяти | Название по точному ключу | Название с факторным сопоставлением |
|---|---:|---:|
| Обученное преобразование, до дообучения | 2/135 | 8/135 |
| Обученное преобразование, после дообучения | 2/135 | 8/135 |
| Отдельный контроль с правильным преобразованием, до | 135/135 | 135/135 |
| Тот же контроль после дообучения | 105/135 | 135/135 |

В контрольном пути после дообучения изменились ключи в 30 контекстных
запросах; факторное сопоставление сохранило названия во всех этих случаях.
Это подтверждает полезность нового способа привязки на данном примере.
Число 135/135 не относится к обученному преобразователю. Правильный код
также не является доказанной верхней границей качества произвольного
алгоритма узнавания: добавочные активации могут влиять на него неоднозначно.

В обученном пути неверных уверенных названий в этом test не было, но
названий вообще мало: 8/135, то есть 5,93%. Нулевая ошибка среди восьми
ответов не устанавливает надёжности на широком распределении.

Связь `primary`–`neighbor` подтвердилась только при seed 23: шесть
положительных экспозиций из шести. Для других двух seeds достаточных
оснований не получилось. Сам обучаемый отбор в этом
test не изменил состав после прежнего удаления точных дублей: до
дообучения было 24 сырых кандидата, после точных дублей 23, после карты
близости также 23. Практический выигрыш нового отбора на этом test не показан.
Контроль двух экземпляров действительно дал
и сохранил обе позиции только при seed 47. В остальных случаях ещё до
отбора не было кандидатов; их нельзя считать успешным узнаванием экземпляров.
На девяти дополнительных посторонних кодах названия не выдавались.
Это небольшая диагностика ответов, не калиброванный детектор неизвестности.

Во всех трёх запусках журнал слов сохранил девять подтверждений,
преобразователи и карта близости во время запросов не менялись.
Общая память получила 54 дополнительных предъявления: шаг 54 → 108.
Само изменение шага не доказывает изменения содержания; для вывода о
дрейфе выше использованы непосредственно изменившиеся `content_key`.

В опыте совместной структуры `coactivation` ни разу не выделила заданную
группу точно (0/12 условий). На исходных совместных историях средний F1
ближайшей заданной группы выше, чем после перестановки колонок:
0,6722 против 0,4167 для одной группы; 0,4913 против 0,3853 для конкурирующих.
Маски зависят от порядка строк. Это свидетельство чувствительности к
совместной структуре вместе с существенными ограничениями, а не готовое
разделение факторов или доказанное превосходство над частотным режимом.

Сохранены [сквозные трассы](results/v03a3-context-integration.json),
[истории консолидации](results/v03a3-coactivation-structure.json) и
[проверки, хэши и независимый пересчёт](results/v03a3-validation.json).
Проверены 230 тестов, Ruff, форматирование, Pyright и компиляция.

Следующий содержательный вопрос: почему преобразователь теряет основания
для части, когда остальные части убраны из входа? Нужно исследовать
зависимость её кластеров от соседнего содержания и требуемую общему чтению
полноту кода. Конкретный ограниченный опыт — сохранить одну часть,
менять или убирать соседние и проследить её целевые биты и кластерные
свидетельства. Параметры следует выбирать на отдельном dev, сохраняя
нынешние результаты как исходную точку. Это приблизит выделение собственных
факторов части и устойчивое узнавание составных наблюдений.
