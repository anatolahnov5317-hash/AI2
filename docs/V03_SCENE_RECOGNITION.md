## Отдельные содержания и необъяснённый остаток

`FactorSceneReader` читает одну общую `CombinatorialMemory` и явно
зарегистрированные учебные портреты. Регистрация не обучает саму память:
она сохраняет её текущие стабильные кластеры и совпавшие совместные признаки.
Входной сырой шаблон и слово внутри портрета не сохраняются.

```python
from text_factors import ContextView, FactorSceneReader

reader = FactorSceneReader(common_memory)
reader.observe_portrait("learned-example-1", canonical_training_sdr)
result = reader.recognize_views(
    [ContextView("view-1", "context-1", whole_transformed_sdr, ())],
    total_views=1,
)
for proposal in result.proposals:
    print(proposal.portrait_id, proposal.coverage, proposal.ambiguous)
for view in result.view_traces:
    print(view.unexplained_bits)
```

Query содержит целый преобразованный SDR, контекст и доступное происхождение.
Правильные границы, учебные ответы и названия в поиск не поступают.
Сначала создаются предложения содержаний, затем обычный `GroundedDialogue`
может сопоставить их свидетельства с подтверждёнными именами.

Для предложения требуется тот же кластер в той же точке памяти и достаточный
совместный фрагмент его рецепторов. Покрытие считается относительно опор
конкретного учебного портрета. Сторонняя часть сцены поэтому не разбавляет
это покрытие увеличением общего знаменателя. Требуются минимум четыре
атома, две точки, три общих атома и покрытие не менее 0.6; фрагмент кластера
должен также достигать порога активации памяти.

Поддержанные предложения сохраняются отдельно. Совпадение факторных атомов
отмечается как неразрешённое перекрытие. Его наличие или отсутствие не
доказывает логическое противоречие, физические границы или независимость
реальных объектов. `unexplained_bits` — остаток без опоры принятых портретов,
а не уже распознанный новый объект.

Новый `content_key` включает совпавшие рецепторы кластера. Ключ предложения
описывает его свидетельства, а не весь исходный вход. Название A внутри
сцены A+B не означает, что B исчезла или вся сцена названа A.

В API допустимо пустое `source_positions=()`. Так отмечается отсутствие
точного соответствия выходных признаков исходным объектам после обученного
преобразования. Обнаружение портрета в выходном коде не выдаётся за выученную
сегментацию исходной сцены.

Чтение ограничено числом портретов, свидетельств, посещений атомов и временем.
Прерванный view не фиксируется как полностью разобранный; предыдущие
законченные представления и статус остановки сохраняются. Изменение системы
координат памяти отвергается. Память не должна обучаться одновременно с
чтением; изменение её шага через callback также проверяется.

`reader.to_dict()` — снимок регистрации для проверки неизменности.
Он не обещает самостоятельной загрузки reader: общую память и правила
кодировки пока должен сохранять вызывающий слой. Новое обучение между
чтениями допустимо, но исчезнувшие или изменённые подписи кластеров больше
не поддерживают прежние портреты. Это отдельное ограничение пластичности.

## Близость с учётом односторонних откликов

Новое поле `RecognitionResult.responses` описывает все законченные чтения,
включая те, у которых нет кандидата. У записи есть контекст, величина
отклика, признак активности и отпечаток логического входного SDR.
Идентификаторы события и представления не влияют на разнообразие входов.
Отмена не записывается как успешно проверенное отсутствие отклика.

```python
from text_factors import AdaptiveContextAffinity

affinity = AdaptiveContextAffinity(pipeline.memory_namespace)
training_result = pipeline.recognize(training_source_sdr)
affinity.observe("observed-training-event", training_result.recognition)
print(affinity.pair_statistics())
restored = AdaptiveContextAffinity.from_dict(affinity.to_dict())
```

Карта использует последние 32 полных события. Для каждой пары записываются
совместная активация, два вида одностороннего отклика и совместная тишина.
Мера `n11/(n11+n10+n01)` требует минимум трёх совместных наблюдений,
трёх разных совместных паттернов и значения не ниже 0.8. Это ограниченная
согласованность активаций, не вероятность или коэффициент Пирсона.

Односторонние отклики ослабляют связь. Старые свидетельства выходят из окна;
связь может исчезнуть и обучиться заново. Журнал идентификаторов для защиты
от повторной доставки хранится отдельно и ограничен 512 событиями по
умолчанию. Достижение ёмкости явно отклоняет новое обучение; бесконечный
поток с выгрузкой журнала не предполагается этой версией.

Высокое совместное узнавание не устанавливает одинаковые правила
преобразования. Подавление дополнительно требует текущих сходных факторных
свидетельств и одного непустого происхождения. В эксперименте целой сцены
такой точной атрибуции нет, поэтому новая карта не подавляет её возможные
разные экземпляры. Неполные результаты не учат карту и сохраняют кандидатов.
Прежний `ContextAffinity`, его состояние и правила хэширования событий
сохраняются для воспроизводимости старых режимов.

## Сквозной стенд и диагностика причин

```bash
timeout 140s text-factors scene-integration --output artifacts/scene-integration.json
```

На новых кодировках сравниваются обученные преобразования, перемешанные
учебные цели, необученные памяти и отдельный правильный вход в общую память.
Результаты целых сцен, изолированных частей и канонических контрольных
смесей разделены. Во время запросов память, портреты, словарь и карта
близости заморожены и проверяются по хэшам.

Оценщик получает цели только после фиксации обычной выдачи. Для одной части
сравниваются два окружения одинаковой плотности и изоляция. В фокусном
выходном блоке учитываются и пропущенные, и лишние биты; правильные биты
соседей не записываются в ошибки этой части.

`evaluation.transform_diagnostics.diagnose_transform_bits` объясняет
пропуски ближайшим блокирующим условием неизменённого readout: нет кластера,
нет устойчивого кластера, нет полного совпадения, недостаточно голосов.
Взвешенные голоса сверяются с фактическим прогнозом. Это описательная
диагностика; она не оценивает пользу изменения порога без нового опыта.

В сравнении процедур есть различия: отдельному портрету достаточно двух
точек, прежнее агрегатное чтение требует четыре точки на представление;
различаются также покрытие и учебные свидетельства названий. Дополнительная
сводка по предложениям с четырьмя точками показывает часть влияния порога,
но не изолирует весь эффект новой архитектуры. Число доступных учебных
названий записывается отдельно для обоих способов чтения.

Канонические смеси A+B и два одинаковых значения на разных позициях
проверяют общее чтение напрямую. Их результаты не относятся к обученному
преобразователю. Портреты и имена позиционные; OR одного и того же кода
A+A не позволяет восстановить число экземпляров, поэтому такого
невозможного требования к модели не предъявляется.

Этот этап добавляет Python API и исследовательскую команду. Терминальный
чат пока использует прежнюю текстовую модель с заданными сдвигами;
он не загружает новый банк преобразований и портретов этой командой.
