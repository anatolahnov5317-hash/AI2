# v0.3.0a3: фиксированный протокол до численного запуска

## Назначение

Связать обученные SDR-преобразования с одной памятью узнавания, проверить
названия по факторным свидетельствам при изменении кластеров, обучить
ограниченную близость контекстных откликов и отдельно исследовать совместную
консолидацию. Это инженерные опыты по мотивам ранее проверенных источников;
автоматическое открытие контекстов и сегментации здесь не предполагается.

## Сквозной опыт

- Новые фиксированные seeds: 11, 23, 47. Кодировки и семейство такие же, как
  в `transform-learning`: три позиции, три значения, блок 32 бита, 6 активных.
- 18 полных сочетаний train, 9 held-out. Первые четыре held-out после
  фиксированной перестановки — dev, остальные пять — test. Все параметры
  ниже заданы до запуска; на dev в этой версии ничего не подбирается.
- Три контекста: две независимо обученные реализации первого отображения
  и одно другое отображение. Принадлежность учебных пар этим контекстам
  задаётся стендом. Близость контекстов учится по откликам, без доступа
  к тому, какие реализации используют одно отображение.
- У преобразователей 512 точек, три эпохи и прежний частотный рецепт.
  Контроли: необученные преобразователи и переставленные учебные цели.
  Идеальное преобразование используется только отдельным оценочным условием.
- Общая память: вход/выход 96 бит, 512 точек, рецептивное поле 32,
  создание/активация 3, probation 2, stable 3, vote 2, частотная консолидация.
  Девять известных канонических частей обучаются по шесть предъявлений
  как автоассоциации. Названия сообщаются лишь для этих учебных частей.
- Преобразователь получает только входные биты. Для оценки целые сцены
  и явно выделенные входные части проверяются раздельно. Части проверочных
  сочетаний знакомы; повторения одной части в разных сценах не считаются
  новыми независимыми содержаниями. Успех при заданных границах не означает
  выделения объектов внутри неразмеченной смеси.
- Названия: старый точный ключ сравнивается с optional factor-режимом;
  min_atoms=4, min_points=2, min_shared_atoms=3, threshold=0.6, margin=0.1.
  Признаки — пары (точка памяти, совпавший входной бит), а не выходные биты.
  Ответы и последующие чтения не создают новых подтверждений.
- Близость: минимум три наблюдения, Jaccard свидетельств не менее 0.6,
  доля положительных экспозиций не менее 0.8. Обучение только по train.
  Подавление требует текущего совпадения происхождения и свидетельств;
  разные экземпляры и явно конфликтующие трактовки сохраняются.
- После исходных измерений общая память получает девять других кодов
  той же плотности по шесть предъявлений, без новых названий.
  Прежние test-вопросы повторяются; преобразователи и словарь не дообучаются.
- Дополнительные контрольные наблюдения: неизвестные коды той же плотности
  и два экземпляра одного входа с разными позициями происхождения.

Раздельно записываются биты прогноза, слово и способ его узнавания, точный
ключ свидетельств, число кандидатов до/после отбора, ошибочное подавление
разных трактовок, неизвестные наблюдения и сохранность названий после
дообучения. Полные цели вычисляет только оценщик после фиксации обычных
прогнозов. Результаты не подменяются идеальным контрольным условием.

## Совместная структура

Две заранее заданные истории: одна совместная тройка с помехами (16×8)
и две конкурирующие тройки с помехами (24×12). Контроль независимо
переставляет каждую колонку, точно сохраняя её частоту. Три фиксированных
seed 101, 211, 307 задают порядок строк и перестановки; это повторные
проверки одной структуры, а не независимые train/dev/test.

Используется неизменённый `coactivation_weights`, три прохода, строгий
порог 0.75, и частотный порог >=0.75. Их шкалы различаются. Отдельно
показываются сырые маски и возможность фактической подрезки при минимуме
трёх рецепторов. Пустая частотная маска не означает, что библиотека
автоматически удаляет весь кластер. Выбор лучшего порядка или порога
по полученному результату не производится.

## Ограничение работы

Конечные датасеты и бюджеты, прогресс по стадиям/seed, явный `incomplete`
при остановке. Каждый отдельный поиск ограничен временем. Для процесса
используется внешний `timeout`; итоговые метрики не публикуются как полные
при незавершённом проходе. Результаты и исходники сохраняются раздельно,
с указанием точного коммита и хэшей исходного кода.
