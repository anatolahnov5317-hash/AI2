# Протокол AI2 v0.2

Этот стенд измеряет поведение памяти на контролируемой задаче. Он не определяет
наличие смысла, причинного понимания или общего интеллекта одним баллом.

## 1. Задача

Все наблюдения — отдельные пятисимвольные строки над алфавитом `abcdefgh`.
Положительные строки имеют одну из четырёх связей крайних символов:
`a...e`, `b...f`, `c...g`, `d...h`. Три внутренних символа варьируются.
Обучение получает только положительные строки, без меток отрицательного класса.

Dev и test содержат поровну положительных и отрицательных примеров. У
отрицательных строк изменена связь концов при точно сохранённых частотах
каждого конца внутри данного разбиения. Поэтому одного знания о частоте
символа недостаточно. В стандартных dev/test представлены все 12 неверных пар
концов, а не только одна перестановка четырёх пар. Полные строки
train/dev/test/noise не пересекаются. Принудительное выравнивание частот и
выбор без возвращения означают, что примеры статистически зависимы.

Это перенос на новые сочетания внутри известного семейства зависимостей.
Другие правила, новый язык, произвольная длина и общие причинные отношения
не проверяются. Разбиение НЕ выдаётся за отложенное семейство задач.

## 2. Методы

| Метод | Доступные данные | Решение |
|---|---|---|
| `ai2` | Положительные строки, SDR и заданные сдвиги | Максимальная знакомость среди контекстов |
| `exact` | Те же строки | Есть ли полная строка в памяти |
| `bigram` | Те же строки | Средняя сглаженная лог-частота локальных биграмм |
| `nearest_sdr` | Те же строки и тот же кодировщик | Максимальный Jaccard со всеми сохранёнными интерпретациями |
| `pair_association` | Те же строки и их позиции | Выбор зависимой пары позиций по train и оценка её совместности |

Последний метод не получает номера крайних позиций или таблицу правильных пар:
он выбирает пару из всех возможных. Его наличие существенно: иначе выигрыш
над локальными биграммами мог бы означать лишь наличие нелокальных признаков.

Все методы получают одинаковую последовательность обучающих предъявлений.
Число уникальных строк и повторов записано явно. Равные данные не означают
равное потребление процессора и памяти: затраты нужно смотреть отдельно.
SDR-конфигурация стенда ограничена 32 кластерами на точку. Это не все стандартные
настройки модели с 20 000 точек.

## 3. Принятие решения и статистика

Основная метрика — balanced accuracy на test после выбора порога по
отрицательным dev-оценкам. Более высокая оценка всегда означает большую
знакомость. При равенстве порогу пример отклоняется.

`--target-fpr 0.05` означает целевую эмпирическую частоту на dev. Это не обещание
FPR <=5% на новых данных. При 16 отрицательных dev-примерах квантиль имеет
очень грубое разрешение; отчёт сохраняет размер калибровки и измеряет test FPR.

В отчёте также есть AUROC с половинным учётом равных оценок, recall, precision,
confusion matrix и номинальные Wilson-интервалы для отдельных долей. Сравнение
точности AI2 с каждым baseline использует парный bootstrap одних и тех же
test-примеров. Единица пересэмплирования — пример внутри этого семейства,
не отдельный бит и не многократный запуск того же примера. Из-за зависимого
дизайна выборки интервалы являются описательной диагностикой, а не строгим
доказательством статистической значимости или гарантией покрытия 95%.

Среднее и стандартное отклонение по seed описывают изменчивость генератора и
случайной памяти в этой постановке. Они не дают интервал переноса на любые
задачи. Порог и все параметры сохраняются; автоматического вердикта «СИИ»
или «научное превосходство» нет.

## 4. Отрицательный контроль и вырождение

Отдельная свежая модель один раз наблюдает каждое окно случайного потока.
Поток выбирается равномерно без возвращения из строк, не занятых остальными
частями набора. Случайные совпадения с положительным правилом не удаляются.
Поэтому это условный случайный фон, а не строго независимая бесконечная IID
последовательность.

Число стабильных кластеров на этом фоне сохраняется как диагностика: случайные
частичные сочетания могут закрепляться. Ненулевое число кластеров само по себе
не является ни успехом discovery, ни доказательством дефекта.

Отдельно сохраняются доля непустых выходов, их плотность и оценки контекстов.
Постоянно пустой выход не получает кредит как полезное инвариантное
представление только за Jaccard=1 между двумя пустыми кодами.

## 5. Воспроизводимость

```bash
text-factors evaluate --seeds 7 17 42 --points 128 --epochs 6 --output artifacts/evaluation.json
```

В JSON сохраняются полные train/dev/test/noise, хеш набора, ModelConfig,
настройки стенда, версии Python/NumPy/пакета, git revision и признак грязного
дерева при наличии checkout, SHA-256 каждого Python-исходника, оценки каждого
примера до порога и итоговые решения. Метрики и пороги можно пересчитать без
повторного обучения. Времена обучения и p50/p95 измеряются на текущей машине.

Хеши не содержат исходники и сами по себе не позволяют повторить обучение.
Для полного повторения нужны соответствующие файлы программы и версии
зависимостей. Сохранённый обученный NPZ стенд не включает: модель создаётся
заново из зафиксированных входов и seed. Исходный прогон v0.2 выполнен из
чистого локального коммита; его точные исходники доступны по GitHub-коммиту,
указанному в отчёте. Последующая typing-правка для NumPy 2.2 проверена полным
повтором и описана отдельно, без изменения исторических JSON.
Локальные git revision/tree описывают checkout запуска, а не обязательно SHA
коммита, созданного через GitHub API. Сопоставлять реализации следует по
`source_sha256` и полному исходному дереву, указанному в отчёте о разработке.

`numpy_payload_bytes_lower_bound` учитывает только постоянные массивы модели;
он не включает Python-объекты, множества, списки, временные массивы и накладные
расходы аллокатора. Это не измерение RAM всего процесса.

Экспериментальная разработка использует этот набор как диагностический.
Подтверждающий результат требует отдельного заранее замороженного набора,
других правил и бюджета точности. Добавление нового baseline после просмотра
первого результата явно отражается в отчёте о разработке.

## 6. Миграция и целостность

NPZ v2 хранит режим обучения и пару контекстов. Запись атомарно заменяет
назначенный файл после успешного формирования временного архива. Загрузка
проверяет структуру ZIP/NPY, типы, размеры, индексы, счётчики и времена.

Ограничения по умолчанию: файл 2 GiB, суммарные распакованные члены 4 GiB,
один массив 1 GiB, метаданные 1 MiB. Первые три границы можно явно изменить
параметрами `load`. Это ограничения входного архива, не гарантия пикового RAM.

v1 читается с собственной кодовой книгой. Продолжение обучения непустой v1
требует явного `assume_training_mode(...)`, потому что восстановить её режим
из отсутствующих метаданных надёжно нельзя.

## 7. Дальнейшие ворота

1. Отложенные семейства зависимостей и ролевые перестановки.
2. Сравнение с обучаемыми структурными представлениями, а не только локальными.
3. Стабильность при изменении размера памяти и длительности потока.
4. Явное связывание ролей и перенос обучаемых операторов.
5. Предсказание последствий действий и смена скрытых правил.

Микромир v0.2 — положительная проверка протокола шага 5 с двумя заданными
гипотезами, а не реализация его обучаемой общей версии.
