# Алгоритм AI2 Text Factors

## 1. Разреженное кодирование

Для каждого допустимого символа `s` и циклической позиции `p` создаётся
детерминированный разреженный код:

\[
E(s,p) \subset \{0, \ldots, D-1\}, \qquad |E(s,p)| = K.
\]

По умолчанию `D = 256`, `K = 8`. Код окна — логическое объединение кодов его
символов. Пробелы, пунктуация и символы вне настроенного алфавита выступают
разделителями и не активируют биты.

Генерация полностью определяется параметром `seed`; одинаковая конфигурация
всегда создаёт одинаковую кодовую книгу.

## 2. Контекстные интерпретации

Контекст `c` циклически сдвигает позицию каждого символа:

\[
T_c(s,p) = (s, (p+c) \bmod P).
\]

Модель вычисляет все `context_count` интерпретаций и выбирает вариант с
максимальным свидетельством уже накопленной памяти. При равенстве выбирается
контекст с меньшим номером, поэтому холодный старт воспроизводим.

## 3. Комбинаторное пространство

Каждая точка `j` случайно выбирает без повторений `R` входных битов:

\[
C_j(x)=\sum_{i \in R_j}x_i.
\]

Если `C_j(x)` не меньше `create_threshold`, пересечение активного входа с
рецептивным полем сохраняется как локальный кластер. Точка заранее связана с
одним выходным битом.

В памяти не допускаются:

- одинаковые кластеры одного выходного бита;
- кластеры короче порога активации;
- превышение `max_clusters_per_point`.

## 4. Активация и консолидация

Для кластера `M` считается частичное совпадение:

\[
P(M,x)=|M \cap x|.
\]

Кластер активен при `P >= activation_threshold`. Он проходит три стадии:

1. `TEMPORARY` — единичное наблюдение;
2. `PROBATION` — повторяющаяся комбинация;
3. `STABLE` — устойчивый фактор, допущенный к формированию выхода.

На границах стадий сохраняются только биты, присутствовавшие как минимум в
`prune_keep_ratio` частичных активаций. В режиме с учителем кластеры с высокой
частотой ошибочной активации удаляются. Деление выполняется только после
накопления достаточного числа наблюдений.

## 5. Выходной факторный код

Для каждой точки определяется максимальное качество совпадения со стабильным
кластером. Выбирается самый высокий уровень качества, на котором активно не
меньше `min_active_points`. Связанные с этими точками выходные биты образуют
разреженный факторный код.

`top_factors()` ранжирует выходные биты по суммарной поддержке стабильных
кластеров. `explain_factor()` сопоставляет биты кластеров с исходными кодами
«символ–позиция» и возвращает наиболее сильные связи.

## 6. Отличия от VB.NET-прототипа

| Область | Прототип | AI2 Text Factors |
|---|---|---|
| Случайность | глобальный `Rnd()` | локальный фиксируемый seed |
| Идентификаторы | `GetHashCode()` объекта | явные ключи и массивы |
| Кириллица | отбрасывается | поддерживается по умолчанию |
| Консолидация без учителя | нулевые пороги | обязательные повторения |
| Границы массивов | возможен индекс 32 | совпадения хранятся как числа |
| Вместимость точки | проверка с off-by-one | строгий предел |
| Сохранение | отсутствует | сжатый NPZ без pickle |
| Проверка | ручная WinForms-визуализация | API, CLI, unit tests и CI |
| Объяснение | отладочные строки | ранжированное свидетельство концептов |

## 7. Ограничения MVP

- Циклические контексты пока заданы, а не обучаются.
- Фактор объясняется корреляцией с кодами, а не полноценной семантикой.
- Текущая структура кластеров оптимизирована для прозрачности; на больших
  корпусах понадобится пакетное представление и ускорение Numba/JAX/PyTorch.
- Для научного вывода нужны заранее определённые метрики и сравнение с
  n-граммами, MinHash/LSH, тематическими моделями и нейросетевыми эмбеддингами.
