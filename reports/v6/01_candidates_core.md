# AI2 v6 — блок 1 из 3: кандидаты смысла и связь с ядром

Дата: 20 сентября 2026 года. Статус: первый блок реализован и проверен локально.
База — `05e22df941d7f51ef2c2f33813e5e0a4f3c7ff02` из `implementation/v05-learned-dialogue`.
Рабочая ветка — `implementation/v06-block1-candidates`; main и прежние PR не изменялись.

## Что изменилось

Раньше `LearnedSession.respond` получал один смысл или отказ, а `score_interpretations`
не участвовал в рабочем выборе. Теперь порядок такой:

1. Получить исходный языковой разбор и оценки обученных компонентов.
2. Построить ограниченный набор согласованных структур с привязками ролей к токенам.
3. Сравнить полные событийные кандидаты с одной версией общей факторной памяти
   и одним состоянием мира.
4. Сохранить неопределённость при близких оценках либо выбрать кандидат.
5. Передать выбранное событие существующему механизму динамики и атомарной записи мира.

Поиск хранит до 8 гипотез и ограничен 512 расширениями, а не только числом конечных
вариантов. Для рабочего чата выделено до 0,4 секунды на предложение кандидатов и
до 0,8 секунды на сравнение всей группы, внутри прежнего общего бюджета реплики.
Проверка общего бюджета доходит до чтения памяти. Лимит или неполный результат
сравнения не превращаются в отрицательную оценку непросмотренного кандидата.

Новые контракты разделяют исходное наблюдение, версию гипотезы и принятое событие.
Сохраняются текст сообщения, источник и номер такта; ID кандидата; смысл, позиции
связанных слов и недостающие роли; версия модели, контекста и предшествующих фактов;
ID событий, от которых зависел входной мир; факторные контексты, портреты и основания
выбора. Наблюдение не переписывается при выборе другой трактовки.

`FactorSceneReader` теперь возвращает `ContextResponse` для каждого завершённого
представления, включая представления без отклика. Эти записи принимаются
`AdaptiveContextAffinity`; чтение, прерванное лимитом, не выдаётся за завершённое.
Учитывается отдельный порог узнавания портрета. Эта правка соединяет форматы;
обучение согласованию и сам механизм внимания относятся к блоку 2.

В диагностике сессии сохраняется весь ограниченный набор кандидатов. Загрузка
проверяет происхождение, выбранный смысл, единообразие версии памяти и соответствие
предшествующему миру. Старые сессии без новых диагностических полей продолжают
читаться. Новые записи сохраняются в существующем ограниченном окне истории;
долговременного архива отвергнутых трактовок в этом блоке ещё нет.

Среда: Python 3.12.14, NumPy 2.3.5, один поток OpenBLAS/OMP. В этой среде Pyright
получил дополнительный путь к установленному NumPy через временную конфигурацию;

лимит процесса 180 секунд и 4 GiB адресного пространства. RSS — максимум отдельного
рабочего процесса, а не сумма памяти всех его дочерних процессов.

В первоначальном новом тесте ожидался пустой список, тогда как API мира возвращает
пустой кортеж. Исправлено ожидание; поведение модели ради этого теста не менялось.

При сверке итогового журнала обнаружены два отсутствующих результата из одной
серии CLI, хотя процесс вернул 0. Причина пропуска по доступному журналу не
установлена. Эти результаты не были зачтены: обе проверки повторены отдельно и
прошли. В запускателе добавлена обязательная сверка всех запрошенных ID с журналом.
Отдельная проверка с ранним `os._exit(0)` подтвердила, что такой случай больше не
помечается успешным. Исходная и повторная серии используют одинаковый хеш кода
и тестов; [сверенный протокол](results/block1-verified.json) перечисляет все 683 ID.

## Проверка поведения

Использован неизменённый численный checkpoint `docs/results/v05_model_42.json`,
seed 42. Перенастройка весов на результаты не выполнялась. Это открытые
разработческие примеры, часть из которых использовалась при отладке; они не являются
новой независимой проверкой языкового переноса.

| Набор | Результат | Что установлено |
| --- | --- | --- |
| 12 прежних development-структур | покрытие 12/12; итоговый выбор 12/12 | Сохранено поведение знакомых конструкций. Старый разбор также давал 12/12. |
| Два примера неоднозначного местоимения | 2/2 | Реальные языковые альтернативы дошли до факторной памяти; она участвовала в выборе. |
| Две перестановки состояния плюс нерелевантный факт | 3/3 | При одинаковых вручную заданных кандидатах релевантная память меняет выбор; факт о другом предмете не разрешает неоднозначность. |
| Два неполных ввода | 2/2 без фактов | Участники и совершившееся действие не выдуманы. |

Пример: для «Он передал книгу Пете» при двух возможных мужских референтах
предложены варианты с Петей и Мишей. В данном ограниченном банке опыта поддержан
вариант передачи от Миши Пете; исходный однозначный разбор отказывался отвечать.
Это показывает участие ядра, но не доказывает логическую невозможность другой
трактовки в реальном языке: знакомость ситуации не равна истине.

Если оба варианта одинаково поддержаны, сохраняются альтернативы и запрашивается
уточнение. Другие тесты проверяют отсутствие записи мира при таймауте, неполной
группе оценок и ограничении числа расширений; неизменность параметров; сохранение
и продолжение сессии; отказ от смешивания версий памяти и контекста.

На 12 знакомых структурах одно измерение предложения и выбора заняло 3,72–5,95 мс,
медиана 5,74 мс, без загрузки модели и генерации ответа. Эта маленькая выборка
не является оценкой задержки длинного диалога или гарантией для другого компьютера.
[Полные трассы примеров](results/block1-development.json).

## Границы первого блока

- Классификаторы и веса v0.5 сохранены. Добавлен ограниченный структурный поиск;
  новый последовательный языковой кодировщик не обучался.
- Словарь алиасов, типы ролей, проверки рода, пороги и правила построения дерева
  остаются явно заданными инженерными ограничениями.
- Для «Маша передала» сохранены наблюдаемое упоминание и неопределённая структура;
  точный предикат этого незавершённого префикса модель ещё не восстанавливает.
- Поддержка факторных представлений не суммируется как независимое голосование;
  полное согласование, поиск по архиву, возврат и пересмотр прошлого — следующие блоки.
- Хранятся консервативные зависимости от событий, составлявших входной мир;
  точная минимальная причинная зависимость каждого балла ещё не выделяется.
- Полная оценка на новых отделённых историях и отключение механизмов запланированы
  на блок 3. Улучшение свободного диалога и преимущество над другими моделями не заявляются.

## Воспроизведение и продолжение

Команды для Linux/macOS/WSL из корня рабочей ветки, с установленными зависимостями:

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 scripts/run_test_batches.py --output /tmp/ai2-v6-block1-tests
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python3 scripts/evaluate_block1.py --output /tmp/ai2-v6-block1-development.json
python -m text_factors learned-chat --model docs/results/v05_model_42.json --state learned-session.json
```

Для продолжения прерванного запуска тестов добавить `--resume` с тем же каталогом,
набором тестов, версиями и конфигурацией. Смена исходников требует нового каталога:
старые результаты нельзя незаметно объединять с другой реализацией.
