# P14–P15: пересмотр зависимой истории (открытая разработка)

Дата: 2026-09-23. Основа: исследовательский блок 2, без независимой
приёмки русского пилота.

`DependencyGraph.ordered_affected(changed_ids)` строит топологический порядок
всех достижимых зависимостей, а не выбирает факты по похожему имени или теме.
Узел с двумя родителями обрабатывается только после обоих. Цикл явно
отвергается. Хеш графа фиксируется на время работы.

`RevisionJob.start` принимает `graph`, `state_version`, исходные значения
узлов и адреса изменившихся узлов. Он сразу выдаёт `pending_claim_ids` со
всеми затронутыми ID; независимые узлы в список не входят. Каждый
`run_batch` вычисляет предложения по текущим значениям непосредственных
родителей и пишет номер позиции вместе с результатами во временный файл,
затем атомарно заменяет checkpoint. Порция публикуется только после записи
файла. Если процесс погиб внутри порции, после `resume` она вычисляется
повторно: обработчик **обязан быть чистой функцией без внешних побочных
эффектов**. До `commit` расчёт остаётся отдельным, а доступ к
`materialized_state` запрещён.

Неразрешённый родитель делает зависящий от него узел неразрешённым.
`commit` проверяет свежую версию исходного состояния, его хеш и хеш графа;
при изменении основы ничего не публикует. После коммита неразрешённые ID
остаются в `pending_claim_ids`, а независимые данные остаются исходными.
В сетевом режиме `RevisionJob.start(... barrier=store, revision_id=...)`
записывает все затронутые ID и новую эпоху через транзакционный API P16
**до** создания checkpoint; при сбое записи они остаются заблокированными.
`finish_barrier` вызывается после коммита job и проверки соответствия
сохранённого снимка пересчитанному; P16 проверяет начальную эпоху под
общей блокировкой публикации ответа. Если результат содержит неразрешённые
факты, online job запрещает finish и сохраняет pending. Для восстановления
такого job на новой основе нужен явный отменяющий переход, который текущий
API не даёт. `RevisionJob` **не применяет** результат к `RealDataEngine` и
не выполняет долговечное переключение рабочей версии: это обязанность
интеграционного слоя. Отдельный реестр источников должен подтверждать права
при выдаче; версия состояния не является правом доступа.

Открытые профильные тесты проверяют косвенное исправление с двумя
родителями, изоляцию другой темы, 600 зависимых узлов с маленькими порциями
и бюджетом, отказ на цикле или чужом/повреждённом checkpoint, неизвестный
родитель, отказ второго воркера записать устаревший checkpoint и реальное
аварийное завершение дочернего процесса посреди порции с восстановлением.
В 12 профильных тестах отдельно участвует настоящий SQLite барьер P16:
отзыв источника во время job меняет эпоху, повторная активация отклоняется
и pending сохраняется. Это синтетические инженерные сценарии, не метрика
качества пересмотра на реальных размеченных историях.
