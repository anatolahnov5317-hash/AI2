## Проверенная исходная граница

`learning/understanding.py` имеет конечный набор из четырёх предикатов
`locate/move/give/have`. После обучения на штатных примерах он вернул для
трёх одинаково заданных синтетических development-реплик:

| Реплика | Результат прежнего обученного маршрута | Новый кандидатный маршрут |
|---|---|---|
| Два события, «вчера не передал» и «затем исправила непонятный ключ» | `multiple_events_unsupported`, целый разбор пуст | Два события, изученная связь `after`, роли и отрицание/время сохранены; `непонятный` оставлен в `unexplained` |
| «Ольга передала мяч Сергею.» | `unknown_lexeme` | Событие `transfer` с разными ID участников и объекта |
| «Вера осветила зал.» | `unknown_lexeme` | Без нового обучающего примера нет события; после отдельной разметки связи `осветила → illuminate` появляется кандидат `illuminate` |

Это сопоставление поведения на **трёх придуманных строках**, а не измерение
F1 или полезного покрытия на независимом документальном корпусе. Прототипу
передаются готовые упоминания с `instance_id`; прежний парсер не получает
эквивалентной внешней подсказки, поэтому цифры двух маршрутов как независимое
сравнение качества здесь не сопоставимы.

## Что сделано

- `real_data/open_semantics.py`: обучение `OpenSemanticModel.fit` на локальной
  разметке `LabeledText` (поверхность предиката, произвольный ID отношения,
  упоминания, роли, подсказки отрицания/времени, при наличии — направленная
  аннотированная связь между событиями). В код не вшиты названия предметных
  отношений, имён, отрицательных и временных слов. Неподтверждённые и
  конфликтующие cue ведут к локальному пропуску.
- `parse` на готовых упоминаниях строит **кандидатный** `SemanticGraph` версии
  `ai2-supervised-event-graph-v1`: события, роли→ID экземпляра, cue offsets,
  `negated`, выученную метку времени, направленные event links и остаток
  `unexplained` в Unicode codepoint offsets. Есть `source_id`, версия, SHA
  входного текста и отпечаток модели; JSON-представления графа и модели
  проверяются при обратной загрузке. Неизвестное слово или символ рядом с
  известным событием не удаляет найденное событие и снимает `complete`.
- Тесты на два события, роли при замене действующих лиц, два одинаковых слова
  с **разными** `instance_id`, отрицание, время, добавление нового отношения
  лишь через обучающий пример, связь `after` через аннотированное «затем»,
  переставленный порядок участников при **отдельно обученном расположении и
  внешних падежных метках**, отказ при отсутствии этих меток, неизвестный
  фрагмент, конфликт меток, отсутствие роли, повреждённый JSON,
  вложенные упоминания и промежуточную неизвестную клаузу. Все тесты
  полностью синтетические и открытые; закрытый набор не читался.

Минимальный вызов после собственного разделения train/development и разметки:

```python
from text_factors.real_data.open_semantics import (
    IdentifiedMention,
    LabeledEvent,
    LabeledText,
    OpenSemanticModel,
    Span,
)

train = LabeledText(
    "Анна передала ключ Борису.",
    (
        IdentifiedMention("a", "person:anna", Span(0, 4), "person", "nom"),
        IdentifiedMention("k", "key:1", Span(14, 18), "thing"),
        IdentifiedMention("b", "person:boris", Span(19, 25), "person", "dat"),
    ),
    (
        LabeledEvent(
            "transfer",
            Span(5, 13),
            (("actor", "a"), ("object", "k"), ("recipient", "b")),
        ),
    ),
)
model = OpenSemanticModel().fit((train,))
graph = model.parse(
    "Ольга передала мяч Сергею.",
    (
        IdentifiedMention("o", "person:olga", Span(0, 5), "person", "nom"),
        IdentifiedMention("x", "ball:1", Span(15, 18), "thing"),
        IdentifiedMention("s", "person:sergey", Span(19, 25), "person", "dat"),
    ),
    source_id="development-document",
    source_version=1,
)
candidate = graph.to_dict()
assert candidate["events"][0]["relation_id"] == "transfer"
```

## Ограничения и необходимая интеграция

Это **отдельный** исследовательский API, он не подменяет
`LearnedUnderstanding`, не пишет `RealDataEngine` и не отвечает в чате.
У существующего `Claim` нет отдельного поля отрицания; `negated` сохраняется
в этом версионированном графе, но перенос в `Claim` с миграцией схемы и
проверкой оснований ещё нужен. Превращать кандидатный граф в `ASSERTED`
автоматически нельзя.

Границы: упоминания, их ID и падежные метки получаются **из внешней разметки**;
самостоятельного морфологического разбора здесь нет. Вложенные/перекрывающиеся
упоминания отвергаются; отношение узнаётся по уже размеченной форме cue,
а роли — по обученному расположению, типу и при совпадающих типах по внешней
падежной метке. Если падежей двух людей нет, модель отказывается назначать
роли; новый порядок требует отдельного обучающего примера. Незнакомые формы
глагола, две клаузы без разделителя,
несколько триггеров в одной клаузе, анафора, масштабный русский текст,
датировка реальными календарными датами, объекты без правильных ID и
неизвестные отрицания пока не решены. Временные ярлыки и `after` получены
только из ручной разметки; они не доказывают фактическую последовательность
событий или причинность.
