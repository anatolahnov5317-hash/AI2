# P04: ограниченный поиск предыдущих упоминаний

Статус: **эксперимент на открытых train/validation**, не прохождение P05.
Данные: прежний англоязычный GUM pilot, 20 train / 4 validation документа;
четыре ранее открытых test-документа здесь не использованы. Исходная выборка
зафиксирована в `docs/GUM_PILOT_MANIFEST.json`. Рабочий вход для запуска
содержит только ключи `schema`, `train`, `validation`; скрипт отвергает test.

Воспроизводимость: seed 17; 6 эпох; 4096 hashed features; ширина span 4;
бюджет antecedent 32; mention threshold 0.5. SHA-256 train
`ef13eeafe7bfe2ab479c087bdec9de0fbc05618d46acd081c7ea74e1f122995a`;
validation `754190cea7125d0806d4a028a2c04901e148a0e5dc7ac64cd470844e1c4fa144`;
модель `66ffd53d51511e5ba1a8e5e65cc83750fb0c2a3b38c1fef79894eeff627acd08`;
исходная policy `06dbde20787fe39b3a1b333af2860d2909c6b842fd4e667ce2be475865e63956`.

При текущем recency 517/926 gold границ не восстановлены, 69/502 повторных
упоминаний имеют ближайшего известного antecedent за окном, ещё 155/502
теряются из top‑3 даже при эталонных границах. Новая ablation резервирует до
8 из тех же 32 позиций для ранее встреченной строки (Unicode casefold);
вариант prefix4 также рассматривает однословные формы с общими первыми 4
буквами и разницей длины до 3. Предлагаются только предыдущие упоминания;
неизвестные и омонимы не превращаются в автоматический выбор сущности.

| Стратегия | Top‑3 при gold границах / 502 | Top‑3 при предсказанных границах / 502 | Максимальная проверенная precision при ≥10 решениях | Порог 90%, ≥10 |
|---|---:|---:|---:|---|
| Последние 32 | 278 | 113 | 8/11 = 72,7% | не достигнут |
| Точная строка + последние | 329 | 145 | 9/10 = 90,0% | достигнут на validation |
| Точная строка + prefix4 + последние | 329 | 145 | 9/10 = 90,0% | достигнут на validation |

Точное сравнение увеличило число найденных кандидатов, но при 10/926 принятых
связях покрытие составляет ~1,1%. Граница 90% достигнута ровно на одном
неправильном решении; выбор порогов проводился на этих же 4 документах.
Это не независимое подтверждение качества, а подсказка для следующей
архитектурной итерации. Prefix4 не дал добавочного выигрыша. Русские формы
проверены только детерминированными тестами, качество на русских документах
не измерено. Штатный inference и существующая policy не изменены.

Весь эксперимент (обучение и три стратегии) записан в соседнем JSON, включая
digest, конфиг, время и peak RSS. Повтор без внешнего baseline дал те же четыре
SHA-256 и метрики; обучение заняло 25,19 с, весь запуск 99,74 с; максимум
процесса 54 060 KiB. Самый длинный validation документ `GUM_news_iodine`
(5931 символ, 275 предсказанных упоминаний) обрабатывался стратегией exact
6,718 с; максимальный RSS включает модель и весь процесс.
Для нового утверждения нужен отдельный,
заранее замороженный русскоязычный pilot и новая независимая закрытая P05.
Старые открытые GUM test и academic holdout подходят только для регрессии.

Повторить после импорта закреплённой версии GUM с помощью
`scripts/prepare_gum_mentions.py` и экспорта только train/validation в
`public.json` по `docs/GUM_PILOT_MANIFEST.json`:

```bash
PYTHONPATH=src python scripts/diagnose_identity_retrieval_dev.py \
  --public-data public.json \
  --output reports/real-data/p04_identity_retrieval_validation_20260923.json
```
