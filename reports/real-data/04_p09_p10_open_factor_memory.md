# P09–P10: частичные наблюдения и независимые группы

Дата: 2026-09-23. Статус: **инженерная проверка на открытом синтетическом
материале**. Этот отчёт не открывает закрытый набор, не подтверждает русский
пилот и не заменяет приёмку P09–P11 на независимых историях.

## Дефект до изменения

`SparseTransform` складывал положительные счётчики по числу предъявлений, а
`ContextRegistry.learn` использовал для выбора контекста также те целевые биты,
которые не наблюдались. Воспроизводимый пример (ширина 32 бита):

| Обучение из одного семейства A | Независимые B и C | Прежний прогноз для `(1,)` |
|---:|---:|---|
| 1 предъявление `(1,) → (10,)` | По одному `(1,) → (11,)` | `(11,)` |
| 50 предъявлений `(1,) → (10,)` | По одному `(1,) → (11,)` | `(10,)` |

Разница происходит только из повторной подачи A. Второй случай: порог создания
контекста `0.6`, первая история `(1,) → (10,)`, следующая история с целью
`(10, 11)`, но наблюдаемым множеством только `{10}`. Прежний `score=0.5` и
появлялся новый контекст; неизвестное `11` ошибочно воспринималось как часть
неподтверждённого целевого состояния.

## Изменение

- Для каждого `(group_id, source_bit, target_bit)` сохраняется один голос за
  присутствие или подтверждённое отсутствие. Повторы одной группы не повышают
  вес; если редакции одной группы противоречат друг другу, голос становится
  неопределённым. `MAX_GROUP_VOTES=100000` ограничивает размер этого слоя:
  превышение отвергается до изменения состояния.
- Явная `observed_target_bits` теперь ограничивает оценку контекста известными
  битами: `target_code ∩ observed_target_bits` — присутствие,
  `observed_target_bits \ target_code` — подтверждённое отсутствие, остальные
  неизвестны. Без маски прежние вызовы сохраняют трактовку «только
  положительные свидетельства». Пустая маска при обучении отвергается.
- `support_for(source_bits, target_bit)` возвращает отдельно число независимых
  групп за и против. Исторические счётчики из старого JSON не получают
  искусственно приписанной независимости. Новая сериализация сохраняет голоса
  групп, проверяет их при загрузке и не усиливает их после replay.
- `ContextRegistry.learn` по-прежнему открывает контексты из пар наблюдений,
  без переданного правильного ID контекста; `predict(context_id, source_bits,
  limit=...)` выполняет source-only чтение без обновления.

Пример чтения **до** записи:

```python
before = registry.predict(context_id, (1,), limit=4)
known = (10, 11)
registry.learn(LearningEpisode("e3", "family-3", (1,), (10,), known))
```

## Заранее описанная открытая проверка

`scripts/evaluate_p09_p10_open.py` использует только синтетические битовые
эпизоды. Обучение содержит семейства `train-A`, `train-B`, `train-C`:
`A → 10` повторяется 50 раз; `B → 11` и `C → 11` встречаются один раз.
Отдельные `dev-D` и `dev-E` проверяют результат `11`; их группы не подаются в
`fit`. Оба метода читаются на замороженном состоянии **до** каких-либо записей
development. Контроль — тот же `SparseTransform` с частотным подсчётом по
предъявлениям без `group_id`.

| Проверка | Частотный контроль | Голоса независимых групп |
|---|---:|---:|
| Корректные source-only прогнозы на двух dev-группах до записи | 0/2 | 2/2 |

Голосов за бит 10 у новой памяти 1, за бит 11 — 2; число повторов A остаётся
видимым в числе эпизодов, но не в подтверждении. Отдельная пара частичных
историй с известным битом 20 переиспользует один контекст; отличающееся
наблюдение с битом 30 создаёт второй. Регрессия проверяет отрицательный бит,
неизвестный бит, противоречивые редакции, старый формат состояния, лимит и
повторный импорт после сериализации.

Команды повторения:

```bash
PYTHONPATH=src python scripts/evaluate_p09_p10_open.py
PYTHONPATH=src python -m unittest tests.test_p09_p10_factor_memory tests.test_real_data_primitives -v
```

## Что ещё требуется для приёмки

Синтетическая проверка специально устроена так, чтобы обнажить дефект
повторных историй. Выборка из двух development-групп и 6 обучающих групп не
позволяет оценить риск, обобщение или выигрыши на произвольных задачах. Для
реального блока нужны независимые русские семейства документов и версий,
разделение по времени, наблюдаемые части состояния с зафиксированным
происхождением, совместная интеграция с P06–P08/P11 и сравнение прогноза до
записи с простыми контролями на одинаковых новых эпизодах. Исторические
неразмеченные счётчики нельзя считать независимыми подтверждениями.
