# P03: открытая проверка границ упоминаний GUM

Дата: 2026-09-23. Эксперимент относится к **английскому** открытому
исследовательскому корпусу GUM, а не к русскому пилоту P01. Новый закрытый
test не открывался. Исходники и документные разбиения закреплены в
[`docs/GUM_PILOT_MANIFEST.json`](../../docs/GUM_PILOT_MANIFEST.json).
Использованы 20 train-документов (4598 упоминаний) и четыре validation-документа
(926 упоминаний). Только эти два отсортированных списка присутствовали в
переданном диагностике `ai2-p03-public-splits-v1`.

| Зафиксированный вход | SHA-256 канонического JSON |
|---|---|
| Train | `21b69afcab5eecb9bd4f5d763cf091bbebb8dae670d45856b999d8430877e9cc` |
| Validation | `f7d7d6aaeaf1eb68cf03f893b6cc74c5baf18bbee54347a83591ec839be2dabd` |

Модели обучены заново из этих 20 train-документов текущим алгоритмом
`unicode-char-shape-sparse-logistic-v3`: `seed=17`, шесть эпох,
`feature_dim=4096`, `max_antecedents=32`. Различается только
`max_span_tokens` (4 либо 8); `max_candidates=65536` и остальные
ресурсные ограничения не изменены. Политика выбора порога заново
калибровалась на **тех же четырёх validation-документах**. Поэтому все
последующие F1 являются разработческими, не результатом независимых ворот.

| Метрика на четырёх validation | Ширина 4 | Ширина 8 |
|---|---:|---:|
| Кандидатов до отбора | 13 508 | 26 952 |
| Доступных точных gold-интервалов / 926 | 761 (82,18%) | 851 (91,90%) |
| Выбранный на validation порог | 0,5 | 0,6 |
| TP / FP / FN | 409 / 521 / 517 | 497 / 974 / 429 |
| Exact-boundary F1 | 0,44073 | 0,41469 |
| Вложенные: доступны / 568 | 405 | 493 |
| Вложенные: найдены / 568 | 197 | 243 |
| Плоские: доступны / 358 | 356 | 358 |

При ширине 4 все 90 золотых интервалов длиной 5–8 токенов, все 53 длиной
9–16 и все 22 длиной 17+ недоступны генератору. При ширине 8 становятся
доступны ровно 90 из них, но число лишних интервалов увеличивается на 453.
Вложенные gold-интервалы оценены по полноте: для ложного предсказанного
интервала нет однозначного деления на «вложенный» и «плоский» без отдельной
политики, поэтому отдельный nested F1 здесь не заявляется. Exact F1 по
длинам доступен в машинном отчёте диагностики.

Три наиболее длинных validation-документа замерялись отдельными процессами;
время относится только к `span_scores`, пик RSS включает загрузку Python,
NumPy и модели. Это наблюдения на текущем исполнителе, не гарантия времени
или памяти на целевом оборудовании.

| Документ (символов) | Ширина 4: секунды / RSS KiB | Ширина 8: секунды / RSS KiB |
|---|---:|---:|
| `GUM_news_iodine` (5931) | 0,222 / 40 436 | 0,573 / 42 676 |
| `GUM_interview_cyclone` (4656) | 0,174 / 40 436 | 0,467 / 42 676 |
| `GUM_news_homeopathic` (3548) | 0,139 / 40 436 | 0,353 / 42 676 |

Ограниченный опыт ранжирования уже предложенных интервалов по максимуму
отклика при совпадающих начале и/или конце (margin 0; 0,02; 0,05; 0,1; 0,2)
не дал прироста F1 на этих же четырёх документах: лучший вариант из
проверенных, сохраняющий почти все интервалы, достиг 0,44060 при ширине 4,
ниже исходных 0,44073; полнота вложенных упоминаний при нём уменьшилась.
Многократный просмотр **тех же validation-меток** не подтверждает
обобщающую способность даже при положительном результате. Ни ширина 8,
ни этот ранжировщик, ни новая политика **не включены** в production-путь.

Дополнительный сравнительный адаптер исходной n-граммной памяти получает
F1 0,12142 на validation при ширине 4, но порог подобран на **той же**
validation. Это не независимый результат и не прежний контроль запоминания
точных поверхностей из Gate 1.

## Как повторить

Взять закреплённый GUM по манифесту, экспортировать **только** отсортированные
train и validation в JSON схемы `ai2-p03-public-splits-v1`, убедиться в
совпадении двух хешей выше. Использовать этот файл для обучения открытых
разбиений, не добавляя test в обучающий артефакт:

```bash
PYTHONPATH=src python - <<'PY'
import json
from pathlib import Path
from text_factors.observations.learning import LearningConfig
from text_factors.observations.learning_commands import train_stages

public = json.loads(Path("artifacts/gum-public-only.json").read_text())
assert set(public) == {"schema", "train", "validation"}
corpus = {
    "schema": "ai2-mention-learning-corpus-v1",
    "provenance": {"annotation_policy": "GUM native coreference; public-only development"},
    "documents": public["train"] + public["validation"],
}
for width in (4, 8):
    config = LearningConfig(seed=17, epochs=6, feature_dim=4096,
                            max_span_tokens=width, max_antecedents=32)
    train_stages(corpus, Path(f"artifacts/p03-width-{width}"), config)
PY
```

Диагностику для каждой обученной модели запустить так:

```bash
PYTHONPATH=src python scripts/diagnose_open_mentions.py \
  --public-data artifacts/gum-public-only.json \
  --model artifacts/p03-width-4/model.json \
  --output artifacts/p03-width-4-diagnostics.json \
  --max-documents 3 --timeout 60
```

Для ширины 8 заменить `width-4` на `width-8`; указанный путь
`artifacts/` является локальным, модели и размеченные тексты в репозиторий
не добавлялись. Проверка воспроизводимости: `python -m unittest
tests.test_p03_diagnostics`; этот тест охраняет открытые split, подсчёт
ceiling/длинных/вложенных интервалов и таймаут отдельного worker.
